# 产品术语表

> **最后更新**：2026-11-22

**一个概念只用一个词。** 同一件事在 PRD、页面规格、架构、代码里必须同名，否则读的人要先翻译一遍。

## 一、站点结构

| 术语 | 唯一含义 | 不要混用的说法 |
|---|---|---|
| **方向** | 笔记的一级分类，`00-计算机基础` 到 `09-大模型`，共 10 个 | 分区、板块、栏目（栏目另有含义，见下） |
| **章节** | 方向下的二级分类，如 `01-数据结构`、`05-Java常用框架` | 分类、小节 |
| **篇** | 最末一级的 Markdown 文件，一个文件一篇 | 文章、文档、笔记（笔记是 10 个方向的集合，不是单篇） |
| **栏目** | 顶部导航里的 6 项：首页 / 全栈笔记 / 全栈项目 / Agent工作流 / 优质资源 / 学习方法 | 导航项、菜单、tab |
| **内容区** | 一个栏目对应的目录，如 `/notes/`、`/workflow/`、`/methods/` | 页面、站区 |
| **目录页** | 某个内容区的首屏全部页，`/notes/index.html` 等，列出结构而不是正文 | 首页、索引、总览 |

## 二、同步与内容源

| 术语 | 唯一含义 | 不要混用的说法 |
|---|---|---|
| **源库** | 内容的唯一事实源，两个独立 Git 仓库 | 源仓库、上游、远端（远端专指 GitHub） |
| **同步产物** | `blog/src/notes/` 与 `blog/src/workflow/`，由 `npm run sync` 生成 | 生成物、拷贝、镜像 |
| **同步** | 跑 `npm run sync`，从源库复制并修补的过程 | 导入、迁移（迁移指换框架或换仓库） |
| **修补** | 同步时对 Markdown 做的三种自动改写（改名 `Cpp`、保护 `${{ }}`、去 H1 编号） | 修正、修复、清洗 |
| **导读** | 源库 README 发布成的页面 `00-内容导读.html` | 前言、简介、README 页 |

## 三、视觉与样式

| 术语 | 唯一含义 | 不要混用的说法 |
|---|---|---|
| **极光背景** | 首页 `home-aurora` 作用域下的网格 + 三团径向渐变，固定于视口 | 背景图、渐变背景 |
| **渐变标题** | 主标题与副标题共用的 `linear-gradient(92deg, #0f9d6b → #2f7df6 → #8b5cf6)` | 彩色标题、彩虹字 |
| **令牌** | 主题的 CSS 变量，如 `--vp-c-accent: #2f845d` | 变量、色值、token（代码里可以是 token，文档里统一叫令牌） |
| **玻璃卡片** | 首页方向卡片：半透明白底 + `backdrop-filter: blur(8px)` + 描边阴影 | 毛玻璃、透明卡片 |

## 四、工作流内容

| 术语 | 唯一含义 | 不要混用的说法 |
|---|---|---|
| **Agent 工作流** | 顶部导航的栏目名，内容是 v1.1.0 的 7 份文档 | AI 工作流、自动化流程 |
| **角色** | 工作流里的 7 个岗位：产品、设计、架构、开发、测试、审查、运维 | 智能体、agent（agent 特指 OpenCode 的 subagent 配置文件） |
| **门** | 需要人放行的检查点，共 8 道（项目实际只用到其中一部分） | 关卡、审批、检查点 |
| **放行** | 人对产物说「可以往下走」，写在产物文首第三行 | 批准（批准可以指「我知道了」，放行只指「可以往下走」） |

## 五、本项目特有

| 术语 | 唯一含义 | 不要混用的说法 |
|---|---|---|
| **妙妙屋** | 站点名「JimBo的米奇妙妙屋」的简称 | 博客（博客指这类站点的形态，不是本项目的名） |
| **学习方法** | 8 个认知模型组成的栏目，已建目录与入口，正文按篇补 | 学习技巧、方法论 |
| **全栈项目** | 把完整交付链镜像成站内文档的栏目，项目按 `00-内容导读` + `01…` 排列 | 作品集、案例（案例指笔记里的实践章节） |
