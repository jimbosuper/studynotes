# 运维手册

> **最后更新**：2026-11-22

## 一、动手前必读

**本项目没有服务器，所以没有「登录机器」这一步。** 能做的操作只有四种：

| 操作 | 怎么做 | 风险 |
|---|---|---|
| 发布 | 推 `master` | 低。构建失败则线上保持上一版 |
| 回滚 | Cloudflare Pages 面板点 `Rollback` | 低，不动代码 |
| 改配置 | 改 `blog/src/.vuepress/*.ts` 后重新推送 | 中。改错会导致构建失败 |
| 查问题 | 看 Cloudflare 构建日志 + 本地复现 | 无 |

**不存在「直接改线上文件」这种操作。** 线上产物是构建结果，改不了也不该改。

## 二、查看

### 2.1 应用状态

| 想看什么 | 在哪看 |
|---|---|
| 站点是否活着 | 浏览器访问 `https://studynotes-90w.pages.dev/`，看状态码 |
| 最近一次部署成功没 | Cloudflare Dashboard → Pages → `studynotes` → Deployments |
| 部署了哪个 commit | 同上，每个 Deployment 条目显示 commit hash 与提交信息 |
| 构建日志 | 同上，点进某个 Deployment |
| 构建耗时 | 同上，日志末尾有 `success VuePress build completed in Xs` |

### 2.2 日志

**本站没有运行时日志。** 静态站点，读者请求直接由 CDN 应答，不产生可查的应用日志。

可看的只有：

| 类型 | 在哪 |
|---|---|
| 构建日志 | Cloudflare Pages → Deployments → 对应条目 |
| CDN 访问统计 | Cloudflare Dashboard → Analytics（有延迟，非实时） |
| 错误率 | Cloudflare Dashboard → 同上报的 4xx / 5xx 曲线 |

**读者遇到 404 不会通知你。** 所以本地构建后的链接扫描（见 `05-测试/03-测试报告/TR1`）比线上日志更重要。

### 2.3 数据库

**没有数据库。** 此项不适用。

### 2.4 定时任务

**没有定时任务。** 唯一的周期性动作是 push 触发的构建。

## 三、启停

### 3.1 启动顺序

**线上不需要「启动」** —— CDN 常驻。要重启本地开发：

```bash
cd blog
npm run sync      # 若源库有更新
npm run dev       # 起开发服务器，端口 8080
```

### 3.2 停止顺序

```bash
# 开发服务器：Ctrl+C
# 清理缓存（改样式不生效时）
npm run clean-dev
```

**没有需要优雅停止的服务。** 无连接池、无后台任务。

**到 Cloudflare 面板删除项目 = 站点彻底下线。** 这是唯一「停止」线上的方式，慎用。

### 3.3 重启

| 对象 | 怎么重启 |
|---|---|
| 开发服务器 | Ctrl+C 后 `npm run dev` |
| 线上站点 | 无法「重启」，只能重新部署（推一次空 commit 或改一行文档） |
| CDN 缓存 | 不需要手动清。静态资源名带内容哈希，改了就换名 |

## 四、改

### 4.1 改配置（环境变量）

| 变量 | 在哪改 | 生效时机 |
|---|---|---|
| `NODE_VERSION` | Cloudflare Pages → Settings → Environment variables | 下次构建 |
| 其他 | 无 | — |

**改环境变量后必须重新部署一次才生效**（Deployments 里点 `Retry deployment`）。

### 4.2 改配置（要重启才生效的）

| 配置 | 文件 | 生效时机 |
|---|---|---|
| 站点标题 / 描述 | `blog/src/.vuepress/config.ts` | 重新构建 |
| 域名 / 作者 / 页脚 | `blog/src/.vuepress/theme.ts` | 重新构建 |
| 导航项 | `blog/src/.vuepress/navbar.ts` | 重新构建 |
| 侧栏规则 | `blog/src/.vuepress/sidebar.ts` | 重新构建 |
| 样式 | `blog/src/.vuepress/styles/*.scss` | 开发时热更新；线上重新构建 |
| 首页内容 | `blog/src/index.md` | 同上 |

**改域名要改三处**，漏一处会让 sitemap / RSS 里仍是旧域名：

```ts
hostname: "https://studynotes-90w.pages.dev",          // theme.ts:6
author: { url: "https://studynotes-90w.pages.dev" },   // theme.ts:9
plugins.sitemap.hostname: "https://studynotes-90w.pages.dev",  // theme.ts:56
```

### 4.3 发版

**标准动作，四步：**

```bash
cd blog
npm run sync          # 1. 源库有更新时才需要
npm run build         # 2. 必须 0 退出码
# 3. 提交（三处同步产物一起提交，见下）
# 4. 推 master
```

**第 3 步最容易漏。** 这三处必须**同一次提交**：

```text
blog/src/notes/
blog/src/workflow/
docs/99-模板文档/
```

只提交其中一处，线上就会与本地不一致。

**提交信息模板**：

```text
feat: 接入全栈笔记 v3（219 篇 + Agent 工作流 v1.1.0）

- sync: 221 篇笔记 / 8 页工作流
- nav: 6 项，新增学习方法
- build: 365 页，0 死链
```

### 4.4 扩容

**不适用。** 静态站点由 CDN 自动分发，没有单机上限。

唯一的「扩容」是内容体积：

| 指标 | 当前 | 上限 | 余量 |
|---|---|---|---|
| 文件数 | 1,841 | 20,000 | 10.9 倍 |
| 单文件 | 6.7 MB | 25 MiB | 3.7 倍 |
| 总大小 | 235 MB | 无硬上限（Pages 建议 ≤ 千兆级） | — |

**加内容时留意图片。** 现在 130 MB 集中在 `00-计算机基础` 的 909 张截图，新增截图会线性增长。

## 五、新增

| 要新增什么 | 怎么做 |
|---|---|
| 一篇笔记 | 去 `../fullstack-notes` 对应章节建 `NN-标题.md` → 回来 `npm run sync` |
| 一份工作流文档 | 去 `../fullstack-workflow/backup-docs` 建文件 → 改 `sync-content.mjs` 的 `WORKFLOW_DOCS` 数组 → sync |
| 一个栏目 | 建 `blog/src/<栏目>/index.md` → 加 `navbar.ts` 与 `sidebar.ts` 条目 → 加首页卡片 |
| 一个方向（第 11 个） | 源库建 `10-<方向>/` → sync 后侧栏与目录页自动出现，但首页卡片要手工加 |
| 一个 MCP / 插件 | `blog/package.json` 加依赖 → `theme.ts` 的 `plugins` 加配置 |

**新增栏目必须同时改三处**：`navbar.ts`（导航）、`sidebar.ts`（侧栏）、`index.md`（首页卡片）。漏一处，栏目能访问但没有入口。

## 六、删除

| 要删什么 | 怎么做 | 注意 |
|---|---|---|
| 一篇笔记 | 删源库文件 → `npm run sync` | 目录页与侧栏自动消失 |
| 一份工作流文档 | 删 `backup-docs` 里的文件 → 从 `WORKFLOW_DOCS` 数组删那一行 | **只删文件不够**，数组里的硬编码会让侧栏指向不存在的页 |
| 一个栏目 | 删目录 → 删 `navbar.ts` 条目 → 删 `sidebar.ts` 条目 → 删首页卡片 → 删 `.vuepress/dist` 后重建 | 四处都要清 |
| 归档旧版本 | **不删**。`docs/99-归档/` 只进不出 | 工作流 §5.1.4 的硬规则 |

**`99-归档` 只进不出。** 要「恢复旧版」的正确做法是从归档 `cp` 出来当新版本升号，不是搬回去顶替当前版。

## 七、备份与恢复

### 7.1 备份现状

| 对象 | 怎么备份 | 频率 |
|---|---|---|
| 代码与文档 | GitHub 仓库（Git 历史即备份） | 每次推送 |
| 内容源 | 两个独立仓库各自的 Git 历史 | 各自推送 |
| 构建产物 | **不备份**。可由代码重建 | — |
| Cloudflare 部署历史 | Cloudflare 自动保留最近若干次 Deployment | 自动 |

**没有独立的备份流程**，因为一切都在 Git 里。唯一的风险是 GitHub 账号或仓库丢失。

### 7.2 恢复演练

**演练过一次（2026-11-22）**：

```text
1. 备份当前 docs/ → $TMPDIR/studynotes-docs-backup/docs-before.tar
2. 重建 docs/ 结构
3. 需要回滚时：tar -xf docs-before.tar -C .   → docs/ 恢复原状
```

**未演练过的场景**：

| 场景 | 预期做法 | 未演练的原因 |
|---|---|---|
| GitHub 仓库被删 | 站点仓库历史丢失；内容源另有两个本地副本可重建站点 | 账号风险低，按内容源重建即可，不做异地镜像 |
| Cloudflare 项目被删 | 重新建 Pages 项目，连同一仓库，重新配置四项 | 重建成本低，无需演练 |
| 本地磁盘损坏 | 从 GitHub 克隆 | 标准操作 |

**单点风险：GitHub 是唯一托管。** 本地不做裸镜像，异地备份成本高于这个站的价值；内容源的两个仓库另有本地副本，站点仓库丢了可从内容源重建。记在架构文档的风险表里。

## 八、回滚

**两种回滚，按影响面选：**

| 场景 | 做法 | 耗时 |
|---|---|---|
| 线上是坏版本，代码没问题 | Cloudflare Deployments → 上一个成功的 → `Rollback` | 1 分钟 |
| 代码本身有问题 | `git revert <commit>` → 推 `master` | 5 分钟 + 构建 3–5 分钟 |

**回滚不需要登机器、不需要改数据库。** 这是静态站的最大好处。

**回滚后要验证三件事：**

1. 首页 200
2. `/notes/` 页数正确（看总览表的合计行）
3. 抽查一篇深层笔记能打开

## 九、故障处理

### 9.1 升级路径

| 故障等级 | 谁处理 | 时限 |
|---|---|---|
| 站点完全不可访问 | 站点作者 | 尽快，无 SLA 承诺 |
| 主栏目 404 / 内容残缺 | 站点作者 | 当天 |
| 单篇内容问题 | 站点作者 | 下次改动时 |

**常见故障对照表**

| 现象 | 先看什么 | 修法 |
|---|---|---|
| 首页 404 | Cloudflare Deployments 最近一次是否失败 | 修代码重推 |
| 页面内容只剩开头几句 | 该篇 `.md` 里有没有裸 `{{ }}` | `npm run sync` 会自动修，重建推送 |
| 构建报 `Element is missing end tag` | 该篇有没有裸 `<xxx>` 占位符 | 加反引号 |
| 构建报 `duplicate ID` | `src/notes/README.md` 的 `permalink` 是否丢了 | 重新 sync |
| 图片全裂 | `src/notes/**/assets/` 是否随同步提交 | 补提交 |
| 线上是旧内容 | 提交里是否含 `blog/src/notes/` | 重新完整提交 |
| 样式改了没生效 | Vite 缓存 | `npm run clean-dev` |

## 十、交接

新接手的人按这个顺序读：

1. `README.md` —— 项目是什么、怎么跑
2. `AGENTS.md` —— 仓库纪律、哪些不能改
3. 本文件第二节与第四节 —— 怎么看状态、怎么发版
4. `03-架构/04-项目环境规范.md` —— 版本、端口、常见问题
5. `05-测试/01-测试策略.md` —— 怎么验证

**三条最容易踩的坑，单独列出来：**

| 坑 | 后果 |
|---|---|
| 手改 `blog/src/notes/` | 下次 sync 全被覆盖，改动白费 |
| 只提交部分同步产物 | 线上内容与本地不一致 |
| 在正文里裸写 `{{ }}` 或 `<xxx>` | 构建直接失败 |
