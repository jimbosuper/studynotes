# 为什么用 vuepress-theme-hope，不自研主题

## 一、Context 背景

这个站要的是**知识库**，不是博客：左侧要目录树、右侧要本页目录、顶部要全文搜索、还要深浅色切换。

从零自己写主题，这四套东西全部要重写：

| 要写的东西 | 从零做的代价 |
|---|---|
| 目录树 | 读磁盘、排序、三层折叠、记住展开状态 |
| 全文搜索 | 建索引、中文分词、按结果跳转高亮 |
| 深浅色 | 两套令牌、首屏不闪、记住选择 |
| SEO 与 RSS | frontmatter、sitemap、atom、canonical |

这四件都是「做出来不难，做好很花时间」的活，而且和内容本身没关系。

## 二、Decision 决定

1. 底座用 VuePress 2（`2.0.0-rc.31`）+ `vuepress-theme-hope`（`2.0.0-rc.110`）
2. 自研的部分只限定在**视觉**：极光背景、渐变标题、玻璃卡片，全部写在 `styles/index.scss`
3. 目录树、搜索、深浅色、SEO 直接用主题能力，不复制一份自己改
4. 主题版本精确锁死，不给 `^`；升级要两者同时升

## 三、Consequences 代价

- 好：目录树、搜索、深浅色、SEO 四件一次到手，省下的时间全部投到内容与首页视觉
- 好：插件生态现成（slimsearch、RSS、sitemap、版权、Markdown 增强）
- 好：遇到问题时官方文档能对上，不必自己排查自研代码
- 坏：**目录树与侧栏的完全控制权交了**——侧栏只能按它给的 `prefix` 语义拼路径，写错就是双重目录
- 坏：**rc 线的版本要跟着升**，主题与 VuePress 必须同步升级，中间不能只升一个
- 坏：**dev 下的入场动画行为由主题决定**（`DropTransition` 在 HMR 下有时不收尾），只能绕，不能改

## 四、Alternatives 放弃过的选项

| 选项 | 做法 | 为什么不选 |
|---|---|---|
| A | 自研主题，只留 Vite + 自己写布局 | 四套东西重写，工期翻倍，且搜索与 SEO 很难超过现成实现 |
| B | **VuePress 2 + vuepress-theme-hope，自研只做视觉** | 选中 |
| C | 换成 VitePress | VitePress 的默认主题没有左侧多级目录树与内置搜索索引，要加两套扩展 |
| D | 换 Next.js / Astro 这类通用框架 | 能做的更多，但这个站只需要文档型布局；多出来的能力全是要维护的配置 |
