# 项目环境规范

> **放行**：已放行 · JimBo · 2026-11-22
> **最后更新**：2026-11-22

> 这个项目只有**两套环境**：本地开发 与 生产（Cloudflare Pages）。没有测试环境——推送 `master` 即上线，中间没有独立的测试集群。
> 这一点和模板的三套环境不同，是项目真实形态，不是遗漏。

## 一、工具版本

**版本精确到小版本号。**

| 工具 | 版本 | 怎么验证 | 为什么锁这个版本 |
|---|---|---|---|
| Node.js | 22.23.4（本地实测） | `node -v` | VuePress 2 rc 与 Vite 需要 Node ≥ 20；Cloudflare 侧固定 `NODE_VERSION=22` |
| npm | 10.9.9（本地实测） | `npm -v` | 随 Node 22 附带 |
| VuePress | 2.0.0-rc.31 | `npm ls vuepress` | rc 线最新可用版本，与 theme-hope rc.110 兼容 |
| vuepress-theme-hope | 2.0.0-rc.110 | `npm ls vuepress-theme-hope` | 与 rc.31 配套；升级需同时升两者 |
| Vite（bundler） | 随 `@vuepress/bundler-vite@2.0.0-rc.31` | `npm ls @vuepress/bundler-vite` | 由 VuePress 决定，不单独定版本 |
| mermaid | `^12.0.0` | `npm ls mermaid` | 源库有 278 幅图，v12 起支持 ESM 直出 |
| sass / sass-embedded | `^1.80.0` | `npm ls sass` | 主题样式走 SCSS；两者都装是为了避开平台二进制问题 |

**版本锁定在配置文件里，不靠口头约定：**

| 文件 | 作用 |
|---|---|
| `blog/package.json` 的 `devDependencies` | 精确到 `2.0.0-rc.31` 这类可复现版本（不给 `^`） |
| `blog/package-lock.json` | 全部传递依赖的锁定快照，体积约 290 KB，**必须入库** |
| `blog/.npmrc` | `legacy-peer-deps=true`、`engine-strict=false`——rc 线依赖声明有不一致，不设这两项 `npm install` 会失败 |
| Cloudflare 环境变量 `NODE_VERSION` | `22` |

**版本没有写进 `.nvmrc` 与 `engines` 字段。** 版本锁定靠两处：本地用 `node -v` 确认，Cloudflare 用 `NODE_VERSION=22` 环境变量。两处写的是同一个值，避免第三处成为漂移源。

**禁止浮动 tag**：本项目的依赖已经全部是精确版本，只有 `mermaid`、`sass`、`vue` 写了 `^`，原因是它们的小版本升级不破坏 API。

## 二、端口与服务

### 2.1 本地端口

| 服务 | 端口 | 地址 | 说明 |
|---|---|---|---|
| 开发服务器（VuePress dev） | 8080 | `http://localhost:8080/` | `npm run dev`，同时监听局域网 `http://<内网IP>:8080/` |

## 四、变量清单

**本项目只需要一个环境变量，且在托管侧：**

| 变量 | 本地 | 生产 | 说明 |
|---|---|---|---|
| `NODE_VERSION` | 不需要（靠本机 Node） | `22` | Cloudflare 构建时选 Node 版本 |

**没有任何密钥。** 站点是纯静态，不连数据库、不调第三方 API、不带 token。`.env` 在 `blog/.gitignore` 里被忽略，属于防御性配置，当前为空。

**构建时需要但不在环境变量里的路径：**

```text
NOTES_SRC      默认 ../fullstack-notes        （仅本地 sync 用）
WORKFLOW_SRC   默认 ../fullstack-workflow     （仅本地 sync 用）
```

这两个只在 `npm run sync` 里读；线上不跑 sync，所以不需要在 Cloudflare 配置。

## 五、环境差异

**差异只允许出现在这张表里。表里没有的项，两套环境必须一致。**

| 项 | 本地开发 | 生产 |
|---|---|---|
| 源库可访问性 | 有（`../fullstack-notes`、`../fullstack-workflow`） | **无**——所以线上不跑 sync |
| 构建命令 | `npm run dev`（dev server） | `npm run build` |
| 是否跑 sync | 首次和内容更新后手动跑 | 永不 |
| 缓存 | `.vuepress/.cache`、`.temp`，可随时删 | CDN 边缘缓存，静态资源靠哈希失效 |
| 图片来源 | `src/notes/**/assets/`（本地文件） | 构建后被复制进 `dist/assets/` |
| 深色模式 | 默认浅色，可手动切换 | 同 |
| 热更新 | 有（Vite HMR） | 无 |

**本地能跑不等于线上能跑的那一处**：本地忘了删 `.DS_Store` 不影响构建，但会把无意义文件带进 Git；本地手动改过 `src/notes/` 而不跑 sync，线上会因为没有提交这些改动而与本地不一致。

## 六、本地依赖启动

**没有外部依赖。** 不需要 Docker，不需要数据库，不需要中间件——这是本站架构的刻意选择：所有状态都在 Git 里。

启动就两步：

```bash
cd blog
npm install        # 首次
npm run sync       # 首次，以及内容更新后
npm run dev
```

**启动顺序不能省 sync。** 直接 `npm run dev` 在全新克隆的仓库上会失败，因为 `blog/src/notes/` 与 `blog/src/workflow/` 是同步产物、默认不在仓库里。

## 七、代码风格工具

**本项目不配 Lint / Formatter。** 这是取舍，不是遗漏：

| 工具 | 有没有 | 现状 |
|---|---|---|
| Prettier | 无 | 代码量小（2 个脚本 + 6 个配置 + 2 个样式文件），靠人工保持一致 |
| ESLint | 无 | 同上 |
| TypeScript 严格模式 | 有（`tsconfig` 由 VuePress 提供） | `.vuepress/*.ts` 类型检查在构建时跑 |
| commitlint | 无 | 提交信息按 `README.md` / `AGENTS.md` 的约定人工遵守 |
| lint-staged | 无 | 无 pre-commit hook |

**真正把关的是构建**：`npm run build` 会暴露类型错误、Vue 编译错误、断链。这比 Lint 更能拦住真实问题。

## 八、常见问题

| 现象 | 原因 | 怎么修 |
|---|---|---|
| `npm run dev` 报 `src/notes` 不存在 | 没跑 sync | `cd blog && npm run sync` |
| 页面内容只剩开头几句 | 正文里有裸 `{{ }}`，Vue 当插值报 TypeError | 把表达式写进行内代码；同步器会自动包 `<span v-pre>` |
| 构建报 `Element is missing end tag` | 正文里有裸 `<provider>` 这类尖括号 | 加反引号或写成 `&lt;` `&gt;` |
| 构建报 `SlimSearch: duplicate ID` | 两个页面映射到同一路径（如 `README.md` 未加 `permalink`） | 给 README 加 `permalink`，或改名 |
| `/notes/` 目录页某条链接 404 | 路径里有 `C++`，构建后变 `04-C__` | 改名 `Cpp`；同步器已自动处理 |
| 云端构建失败但本地成功 | 忘了提交同步产物，或忘了删 `.DS_Store` | 检查 `git status`，同步产物三处一起提交 |
| 改样式后不生效 | Vite 缓存 | `npm run clean-dev` |
| 首屏闪黑 | 系统深色 + 主题首屏脚本晚于首次绘制 | `config.ts` 已注入首屏脚本，改这段会复现 |
