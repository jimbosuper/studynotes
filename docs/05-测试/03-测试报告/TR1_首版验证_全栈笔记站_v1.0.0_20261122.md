### 一条要说明的：TC-18 在 dev 下测不出

**同一个页面，dev 与构建产物表现不同：**

| 环境 | `#main-description` 的 opacity | 结论 |
|---|---|---|
| **`npm run dev`（8080）** | **0** | 元素完全不可见，但渐变背景已正确设置 |
| 构建产物（`dist/` 静态服务，8100） | **1** | 正常显示，渐变生效 |
| 线上（`studynotes-90w.pages.dev`） | **1** | 正常显示 |

**原因在主题的入场动画组件 `DropTransition`**：它用 `onAppear` 把元素设成 `opacity: 0`，用 `onAfterAppear` 恢复成 1。在 dev 的 HMR 环境下，`onAfterAppear` 有时不触发，元素就停在 0。

**这不是我们引入的 bug**，是主题在 dev 下的已知行为。判断依据：

1. 构建产物与线上都正常（上表）
2. 主题源码 `DropTransition.js` 里 `unsetStyle` 明确把 opacity 设回 1
3. 只有 dev 环境复现，且刷新多次不一定复现

**对读者的影响为零**（线上正常）。对开发者的影响：**调试首页时如果发现标题或副标题消失，先切到构建产物看，不要以为是自己样式写错了。**

**这条写进报告而不是修掉**，因为它不是本项目的缺陷；改主题源码去迎合 dev 环境，反而会在升级主题时冲突。

**判据按「产物与线上」取，不按 dev 环境取**：dev 是开发态热更新环境，不是交付物；线上与构建产物才是读者看到的东西，这两处通过了就是通过。

**大屏 1512 / 1920**：布局规则是 1440 以上的断点共用一套（卡片 4 列、正文容器 1160px 居中），所以 1440 通过即 1512 / 1920 同一套规则；逐像素差异属观感，由人工目视确认，不影响验收项。
