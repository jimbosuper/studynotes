米奇妙妙屋想解决什么？

网上讲一个技术的文章很多，但大多停在「它能做什么」，很少回答真正卡住人的三件事：装好了怎么确认真的能用、出了事第一条命令敲什么、放到真实项目里边界在哪。

所以这里不写名词百科，按一条完整的交付链铺开：计算机基础 → 产品 → 设计 → 架构 → 前端/后端 → 测试 → 运维 → 移动端 → 大模型，219 篇，每个环节都能看到上游要什么、下游怎么接。

每一篇都按同一套结构写：先划边界，再给最小可运行验证，最后落到一个完整案例。看完能从「听说过」变成「敢在项目里用，坏了知道先看哪」。

开发编码只占正规项目的 20%，AI 至今没能高质量完成工程，本质仍是黑盒祈祷编程。与其追 Harness、Skills 这类几个月迭代一次的中间产物，不如把精力放在企业级规范开发流程上——Agent 工作流把产品、设计、架构、开发、测试、审查、运维七个角色和八道门写成了可执行的规则，让 AI 的输出有人复核、有门把关，而不是自己写自己签字。

SpringBoot应用框架

JimBo大约 14 分钟方向 05-后端

这篇从 Spring Boot 的约定和版本边界讲起，经过工程创建、自动配置、Starter、配置与 Profile、启动流程、三层结构、Actuator，最后落到打包部署、故障排查和一个可上线的库存服务案例。

学完能独立搭建 Spring Boot 3.5 应用，解释自动配置从哪来，按环境管理配置，并用 Actuator 和日志定位启动与运行问题。

一、Spring Boot 的约定与版本边界

Spring Boot 的约定决定了一个工程「默认不用配什么」：依赖版本由 BOM 收口，Servlet 容器内嵌在应用里，配置按固定顺序加载。先把版本边界划清楚，后面的自动配置、Starter 和 Profile 才不会互相打架。

版本Spring FrameworkJava主要变化

Spring Boot 4.1.x7.x17+当前 OSS 主线，新项目首选
Spring Boot 2.7.x5.3.x8–17已停止维护，不用于新项目
