### 3.1 旧文档残留，两套规范并存

| 段 | 内容 |
|---|---|
| 位置 | `docs/deploy.md`、`docs/writing.md`；引用处 `README.md`、`blog/README.md`、`AGENTS.md` |
| 触发条件 | 读 `README.md` 找部署说明时被指向旧文件；新部署说明在 `docs/06-运维/03-运维手册.md` |
| 影响 | 两套说明并存且已漂移，接手的人判断不出哪份是当前版 |
| 证据 | 旧 `deploy.md` 写「353 页 / 1,814 文件 / 6.5 MB」，实际「365 / 1,841 / 6.7 MB」；旧 `writing.md` 写「仓库体积 259 MB」，实际 `blog/src/notes` 是 162 MB |
| 最小修复 | 删两个旧文件；三处引用改指新文档；`AGENTS.md` 目录树更新 |

**为什么是 P1**：指向错的文档 = 按错步骤操作，属「高概率可见缺陷」。

**修复结果**：已修。删除两个文件；`README.md` 改指 `docs/06-运维/03-运维手册.md` 与 `docs/04-开发/01-代码规范.md`；`blog/README.md` 改指前者；`AGENTS.md` 目录树换成 8 目录完整清单。修复后重扫 `docs/` 内部引用，断链 0。

### 3.2 TD 实施顺序缺少每步产出物

| 段 | 内容 |
|---|---|
| 位置 | `docs/04-开发/02-技术方案/TD1_*.md` 第五节「实施顺序」 |
| 触发条件 | 任何人按这份方案推进时 |
| 影响 | 8 个步骤只有「做什么」，没有「做完能看见什么」，跨会话推进时容易漏步或重复；且缺部署一步，无法判断「上线」何时算完成 |
| 证据 | TD1 的「实施顺序」表第 1–8 步只有「步骤」与「依赖」两列，无产出物；部署配置在另一节，未纳入步骤 |
| 最小修复 | 在实施顺序表补一列「做完能看到什么」，逐步骤写产出物 |

**为什么是 P1**：实施顺序是整份 TD 里唯一被照着执行的表。缺「做完能看到什么」，跨会话推进就退化成凭记忆，漏步与重复都会发生。

**修复结果**：已修。实施顺序表补了「做完能看到什么」列，并从 8 步扩到 9 步（补了部署一步），每步都有可验收的产出物。
