## 五、通过标准

声明「完成」前必须跑通，并附真实输出。

| 检查 | 跑哪条 | 通过标准 |
|---|---|---|
| 构建 | 上一节「构建」 | 退出码 0 |
| 单元测试 | 上一节「单元测试」 | 全部通过，0 skipped |
| 类型检查 | 上一节「类型检查」 | 无 error |
| 风格检查 | 上一节「风格检查」 | 无 error，无新增 warning |

少跑一项不算通过。跑不了要说明原因、影响范围、剩余不确定性。

合进 `test` 后由 CI 跑全量 + e2e 并部署测试环境，报告以 CI 结果为准；流水线定义在 `.gitlab-ci.yml`。本地过了不代表 CI 能过——数据库版本、环境变量、mock 与真实服务的差异会在这一步暴露。

## 六、禁止内容

| 禁止 | 为什么 |
|---|---|
| 改自动生成的目录（`待补充`，如 `dist/`、`src/generated/`） | 下次生成就覆盖 |
| 改已上线的迁移 | 线上数据对不上 |
| 删测试、削弱断言、加 skip / `.only` | 伪造验证 |
| 提交 `.env`、密钥、凭证 | 泄露 |
| 推送到 `待补充`（受保护分支，通常 `main` / `test` / `prod`） | 合并与上线权归人，AI 最高推到 `dev` |
| `git stash`、切换分支 | 多 agent 并发时会 stash 掉别人的改动 |
| 提交不属于本次任务的文件 | 会把别人的工作带进历史 |
| 在 `docs/` 之外新建项目级文档 | 文档只有 `docs` 一处 |

每条都来自真实踩过的坑，新加一条时注明日期与原因。
