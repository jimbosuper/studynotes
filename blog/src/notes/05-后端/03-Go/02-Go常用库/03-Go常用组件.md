# Go常用组件

> 这篇从 `slog` 结构化日志讲起，经过配置加载的优先级、`net/http` 客户端的超时与重试、`database/sql` 的连接池与事务、Redis 客户端的缓存边界，再到组件的装配与关闭顺序，最后落到一个可配置并发的服务健康巡检工具。
>
> 学完能把日志、配置、HTTP、数据库和缓存按统一约定接进一个 Go 服务，给每个外部调用设期限，并在进程退出时按顺序释放资源。

> 版本基线（2026-11-13）：Go 1.24+，`log/slog` 需要 Go 1.21+；HTTP 客户端用标准库 `net/http`；数据库示例用 `github.com/jackc/pgx/v5` 的 `stdlib` 驱动；缓存示例用 `github.com/redis/go-redis/v9`。外部依赖需要 `go get`，没有服务时只读代码不改逻辑。

## 一、slog：结构化日志

这章解决“日志怎么带字段、怎么输出 JSON、怎么脱敏”。`log/slog` 把日志拆成“记录 + 处理器”，字段是键值对，不再拼字符串。

### 1.1 默认 logger 与级别

```go
slog.Info("server start", "addr", ":8080")
slog.Warn("slow query", "table", "orders", "cost_ms", 1200)
slog.Error("connect failed", "err", err)
```

默认输出到 stderr，文本格式：

```text
2026/11/13 10:00:00 INFO server start addr=:8080
2026/11/13 10:00:00 WARN slow query table=orders cost_ms=1200
2026/11/13 10:00:00 ERROR connect failed err="dial tcp: connection refused"
```

级别从低到高是 `Debug`、`Info`、`Warn`、`Error`，默认只输出 `Info` 及以上。

```go
slog.SetLogLoggerLevel(slog.LevelDebug) // 调整默认 logger 的级别
slog.Debug("cache hit", "key", "user:1") // 现在会输出
```

> 边界：`slog.SetLogLoggerLevel` 只影响默认 logger，不影响自己 `slog.New` 出来的实例。库代码不要改全局级别，用注入的 logger。

### 1.2 TextHandler 与 JSONHandler

生产环境用 JSON，采集端按字段解析；本地开发用 Text，人眼友好。

```go
opts := &slog.HandlerOptions{
	Level:     slog.LevelInfo,
	AddSource: false, // 打开会记录文件行号，开销明显
}

text := slog.New(slog.NewTextHandler(os.Stdout, opts))
jsonl := slog.New(slog.NewJSONHandler(os.Stdout, opts))

jsonl.Info("order paid",
	"order_id", "A-1001",
	"amount_cents", 12800,
	"latency", 35*time.Millisecond,
)
```

预期输出：

```json
{"time":"2026-11-13T10:00:00.123456+08:00","level":"INFO","msg":"order paid","order_id":"A-1001","amount_cents":12800,"latency":35000000}
```

`time.Duration` 在 JSON 里是纳秒整数。需要可读值就显式 `slog.String("latency", d.String())`。

> 边界：JSONHandler 每个字段都要编码，热路径上比 Text 慢。日志量大时控制字段数量，不要把整个请求体塞进日志。

### 1.3 属性、With 与 Group

`With` 返回带固定字段的子 logger，避免每行重复：

```go
logger := slog.New(slog.NewJSONHandler(os.Stdout, nil)).
	With("service", "order-api", "env", "prod")

logger.Info("request", "method", "GET", "path", "/api/orders")
logger.Warn("slow", "path", "/api/orders", "cost_ms", 850)
```

输出里每行都有 `service` 和 `env`。`Group` 把字段收进嵌套对象：

```go
logger.Info("payment",
	slog.Group("order",
		slog.String("id", "A-1001"),
		slog.Int64("amount_cents", 12800),
	),
	slog.Group("client",
		slog.String("ip", "10.0.0.8"),
		slog.Int("port", 51234),
	),
)
```

```json
{"time":"...","level":"INFO","msg":"payment","service":"order-api","env":"prod","order":{"id":"A-1001","amount_cents":12800},"client":{"ip":"10.0.0.8","port":51234}}
```

> 边界：`slog.Any` 用反射编码，值里含不支持的类型时输出 `!BADKEY` 或错误串。已知类型用 `slog.String/Int/Duration/Time`，性能更好、输出更稳定。

### 1.4 脱敏与字段改写

`ReplaceAttr` 在每条记录写出前调用，可以改名、格式化时间、屏蔽敏感字段：

```go
opts := &slog.HandlerOptions{
	ReplaceAttr: func(groups []string, a slog.Attr) slog.Attr {
		switch a.Key {
		case slog.TimeKey:
			return slog.String("ts", a.Value.Time().Format(time.RFC3339))
		case "password", "token", "authorization":
			return slog.String(a.Key, "***")
		}
		return a
	},
}
logger := slog.New(slog.NewJSONHandler(os.Stdout, opts))
logger.Info("login", "user", "alice", "password", "s3cret")
```

预期输出：

```json
{"ts":"2026-11-13T10:00:00+08:00","level":"INFO","msg":"login","user":"alice","password":"***"}
```

> 边界：`ReplaceAttr` 对每个属性调用一次，包括 Group 内部，`groups` 参数用于判断层级。脱敏是兜底，真正的原则是根本不把密钥传进日志。

### 1.5 带 context 的日志

`InfoContext` 把 ctx 传给 Handler，自定义 Handler 可以从中取 trace ID：

```go
type ctxHandler struct {
	slog.Handler
}

func (h ctxHandler) Handle(ctx context.Context, r slog.Record) error {
	if id, ok := ctx.Value(traceKey{}).(string); ok {
		r.AddAttrs(slog.String("trace_id", id))
	}
	return h.Handler.Handle(ctx, r)
}

logger := slog.New(ctxHandler{slog.NewJSONHandler(os.Stdout, nil)})
logger.InfoContext(ctx, "query", "table", "orders")
```

| 日志内容 | 建议字段 |
|---|---|
| 请求 | method、path、status、cost_ms |
| 外部调用 | target、attempt、status、err |
| 业务事件 | order_id、user_id、amount_cents |
| 错误 | err、op、retryable |

> 边界：`slog` 不负责采样和异步写。高吞吐服务要在 Handler 外层做采样，或换成支持批量写的实现；每条日志都同步写磁盘会拖慢请求。

## 二、配置：环境变量、文件与优先级

这章解决“配置从哪来、谁覆盖谁、缺了怎么办”。配置在启动时一次加载、校验、冻结，运行中不再读环境变量。

### 2.1 环境变量

```go
port, ok := os.LookupEnv("APP_PORT")
if !ok {
	port = "8080" // 默认值集中在一处
}
n, err := strconv.Atoi(port)
if err != nil {
	return fmt.Errorf("APP_PORT=%q: %w", port, err)
}
```

必填项缺失要启动失败，而不是用空值继续跑：

```go
dsn := os.Getenv("DATABASE_URL")
if dsn == "" {
	return errors.New("DATABASE_URL is required")
}
```

> 边界：`os.Getenv` 无法区分“未设置”和“设置为空”。需要区分时用 `LookupEnv`。环境变量区分大小写，容器编排里统一大写加下划线。

### 2.2 配置文件与严格解码

```go
type Config struct {
	Service   string   `json:"service"`
	Addr      string   `json:"addr"`
	TimeoutMS int      `json:"timeout_ms"`
	Targets   []Target `json:"targets"`
}

func Load(path string) (*Config, error) {
	f, err := os.Open(path)
	if err != nil {
		return nil, fmt.Errorf("open config %s: %w", path, err)
	}
	defer f.Close()

	dec := json.NewDecoder(io.LimitReader(f, 1<<20)) // 配置不该超过 1MB
	dec.DisallowUnknownFields()                     // 拼错的字段直接报错
	var cfg Config
	if err := dec.Decode(&cfg); err != nil {
		return nil, fmt.Errorf("decode config %s: %w", path, err)
	}
	return &cfg, nil
}
```

> 边界：严格模式会让旧版本程序拒绝新增字段。配置文件和程序一起发布时用严格模式；跨团队共享的配置中心接口要允许未知字段。

### 2.3 优先级与合并顺序

约定优先级从高到低：命令行参数、环境变量、配置文件、内置默认值。

```go
func (c *Config) ApplyEnv() error {
	if v, ok := os.LookupEnv("APP_ADDR"); ok {
		c.Addr = v // 环境变量覆盖文件
	}
	if v, ok := os.LookupEnv("APP_TIMEOUT_MS"); ok {
		n, err := strconv.Atoi(v)
		if err != nil {
			return fmt.Errorf("APP_TIMEOUT_MS=%q: %w", v, err)
		}
		c.TimeoutMS = n
	}
	return nil
}

func (c *Config) ApplyDefaults() {
	if c.Addr == "" {
		c.Addr = ":8080"
	}
	if c.TimeoutMS == 0 {
		c.TimeoutMS = 1000
	}
}
```

加载顺序固定为：读文件 → 应用默认值 → 应用环境变量 → 解析命令行参数 → 校验。

> 边界：默认值不要散落在使用处。所有默认值集中在 `ApplyDefaults`，排查“为什么端口是 8080”时只看一个函数。

### 2.4 校验与密钥

```go
func (c *Config) Validate() error {
	var errs []error
	if c.Service == "" {
		errs = append(errs, errors.New("service is required"))
	}
	if c.TimeoutMS <= 0 || c.TimeoutMS > 60_000 {
		errs = append(errs, fmt.Errorf("timeout_ms %d out of range", c.TimeoutMS))
	}
	for i, t := range c.Targets {
		if t.Name == "" || t.URL == "" {
			errs = append(errs, fmt.Errorf("targets[%d]: name and url are required", i))
		}
	}
	return errors.Join(errs...) // 一次返回全部问题
}
```

密钥只从环境变量或密钥管理服务读取，不写进配置文件，不提交仓库：

```bash
# 本地开发：从 .env 注入，但 .env 必须在 .gitignore 里
export DATABASE_URL='postgres://app:secret@localhost:5432/app?sslmode=disable'
export REDIS_ADDR='localhost:6379'
```

> 边界：`.env` 不是标准库能力，很多框架自带加载器；生产环境用编排平台的 Secret 或 Vault，不把密钥烘进镜像。

### 2.5 配置的可见性

启动时打印一次脱敏后的配置，便于确认实际生效值：

```go
logger.Info("config loaded",
	"service", cfg.Service,
	"addr", cfg.Addr,
	"timeout_ms", cfg.TimeoutMS,
	"targets", len(cfg.Targets),
)
```

> 边界：不要打印完整 DSN 和密码。打印“host、port、database”这类可诊断字段即可，密钥字段统一用长度或 `***` 代替。

## 三、net/http 客户端

这章解决“请求为什么卡住不返回、连接为什么越积越多、超时该设在哪”。HTTP 客户端的所有阻塞点都必须有期限。

### 3.1 Client 与 Transport 的超时

`http.DefaultClient` 没有超时，请求可能永久挂起。生产代码自建 Client：

```go
client := &http.Client{
	Timeout: 5 * time.Second, // 整个请求的上限，包含连接、重定向、读 body
	Transport: &http.Transport{
		Proxy:                 http.ProxyFromEnvironment,
		MaxIdleConns:          100,              // 全局空闲连接上限
		MaxIdleConnsPerHost:   20,               // 单主机空闲连接上限
		IdleConnTimeout:       90 * time.Second, // 空闲连接回收时间
		TLSHandshakeTimeout:   5 * time.Second,
		ResponseHeaderTimeout: 3 * time.Second, // 只等响应头
		ExpectContinueTimeout: time.Second,
	},
}
```

| 超时 | 覆盖范围 | 建议 |
|---|---|---|
| `Client.Timeout` | 整个请求 | 业务可接受的最长等待 |
| `TLSHandshakeTimeout` | TLS 握手 | 3 到 5 秒 |
| `ResponseHeaderTimeout` | 请求发出到响应头 | 短于 Client.Timeout |
| `IdleConnTimeout` | 连接池空闲回收 | 60 到 90 秒 |

> 边界：`Client.Timeout` 包含读 body 的时间。下载大文件时用它会把正常传输掐断，应该只设连接和响应头超时，再用 `context` 控制整体预算。

### 3.2 构造请求与复用连接

```go
req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
if err != nil {
	return fmt.Errorf("build request: %w", err)
}
req.Header.Set("Accept", "application/json")
req.Header.Set("User-Agent", "order-api/1.0")

resp, err := client.Do(req)
if err != nil {
	return fmt.Errorf("get %s: %w", url, err)
}
defer resp.Body.Close() // 无论状态码都要关闭

if resp.StatusCode != http.StatusOK {
	// 读掉少量 body 便于连接复用，同时避免把错误页整个读进内存
	_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, 4<<10))
	return fmt.Errorf("get %s: status %d", url, resp.StatusCode)
}

body, err := io.ReadAll(io.LimitReader(resp.Body, 1<<20))
if err != nil {
	return fmt.Errorf("read body: %w", err)
}
```

> 边界：不读完 body 就 Close，连接通常无法复用。错误响应也要 `io.Copy(io.Discard, ...)` 排空，或者接受连接被丢弃。响应体没有大小上限时一定套 `LimitReader`。

### 3.3 错误分类

```go
var netErr net.Error
switch {
case errors.As(err, &netErr) && netErr.Timeout():
	// 超时：可以重试或降级
case errors.Is(err, context.Canceled):
	// 调用方主动取消：不重试
case errors.Is(err, context.DeadlineExceeded):
	// 预算用完：通常不重试
default:
	// DNS、连接拒绝、TLS 失败等
}
```

`http.Client.Do` 返回的 `*url.Error` 包装了底层错误，`errors.As` 能穿透。

> 边界：不要用字符串匹配 `"timeout"` 判断错误。`net.Error.Timeout()` 和 `context` 的哨兵值才是稳定接口。

### 3.4 重试与退避

只对幂等请求和临时故障重试：连接失败、超时、5xx、429。4xx（除 429）重试没有意义。

```go
func doWithRetry(ctx context.Context, client *http.Client, req *http.Request) (*http.Response, error) {
	const maxAttempts = 3
	var lastErr error

	for attempt := 1; attempt <= maxAttempts; attempt++ {
		resp, err := client.Do(req.Clone(ctx)) // Clone 复用请求定义，body 需要可重读
		if err == nil && resp.StatusCode < 500 && resp.StatusCode != http.StatusTooManyRequests {
			return resp, nil
		}
		if resp != nil {
			_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, 4<<10))
			resp.Body.Close()
			lastErr = fmt.Errorf("status %d", resp.StatusCode)
		} else {
			lastErr = err
		}
		if attempt == maxAttempts {
			break
		}

		// 指数退避加抖动：避免所有实例同一时刻重试
		backoff := time.Duration(1<<attempt) * 100 * time.Millisecond
		jitter := time.Duration(rand.IntN(100)) * time.Millisecond
		select {
		case <-time.After(backoff + jitter):
		case <-ctx.Done():
			return nil, ctx.Err()
		}
	}
	return nil, fmt.Errorf("after %d attempts: %w", maxAttempts, lastErr)
}
```

> 边界：带 body 的请求不能直接 `Clone` 重试，body 已被读掉。要么把 body 缓存成 `[]byte` 每次重建 `io.NopCloser`，要么只在 GET/HEAD 上重试。

### 3.5 连接池与压测

连接池太小会在高并发下排队，太大则把压力转给下游：

```go
// 单实例 QPS 目标 500，平均延迟 20ms
// 粗略估算并发连接数 = 500 * 0.02 = 10
// 留 2 倍余量，MaxIdleConnsPerHost 设 20
```

排查连接问题：

```bash
# 查看进程的 ESTABLISHED 连接数
ss -tanp | grep ':443' | wc -l

# 打开 Transport 的调试日志（需要自定义 RoundTripper 或 GODEBUG）
GODEBUG=http2debug=1 ./app
```

> 边界：`MaxIdleConnsPerHost` 默认是 2，高并发下远不够，表现为大量 TIME_WAIT 和延迟抖动。改大之前先确认下游能承受。

## 四、database/sql：连接池与事务

这章解决“连接什么时候建立、连接池怎么配、事务怎么不泄漏”。`database/sql` 是抽象层，具体协议由驱动实现。

### 4.1 打开与验证

```go
import (
	"database/sql"
	_ "github.com/jackc/pgx/v5/stdlib" // 空白导入注册驱动
)

db, err := sql.Open("pgx", dsn) // 只解析 DSN，不建立连接
if err != nil {
	return fmt.Errorf("open db: %w", err)
}
defer db.Close()

ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
defer cancel()

if err := db.PingContext(ctx); err != nil { // 真正建立一次连接
	return fmt.Errorf("ping db: %w", err)
}
```

> 边界：`sql.Open` 几乎不会失败，配置错误要到第一次查询才暴露。启动时必须 `PingContext`，把连接问题挡在流量进来之前。

### 4.2 连接池参数

```go
db.SetMaxOpenConns(25)                 // 同时打开的最大连接数
db.SetMaxIdleConns(25)                 // 空闲池大小，通常等于 MaxOpenConns
db.SetConnMaxLifetime(30 * time.Minute) // 短于数据库/代理的空闲断连时间
db.SetConnMaxIdleTime(5 * time.Minute)  // 空闲连接回收
```

| 参数 | 过小的后果 | 过大的后果 |
|---|---|---|
| `MaxOpenConns` | 请求排队、超时 | 打满数据库连接数 |
| `MaxIdleConns` | 频繁建连 | 空闲连接占资源 |
| `ConnMaxLifetime` | 用到被服务端断开的连接 | 连接长期不轮换 |
| `ConnMaxIdleTime` | 空闲连接堆积 | 频繁重建 |

> 边界：`MaxOpenConns` 要按“实例数 × 单实例连接数 ≤ 数据库上限”计算。Kubernetes 扩容后连接总数会翻倍，配置要留余量。

### 4.3 查询、Scan 与 NULL

```go
type Order struct {
	ID          string
	AmountCents int64
	Note        sql.NullString // 可能为 NULL
}

row := db.QueryRowContext(ctx,
	`SELECT id, amount_cents, note FROM orders WHERE id = $1`, id)

var o Order
if err := row.Scan(&o.ID, &o.AmountCents, &o.Note); err != nil {
	if errors.Is(err, sql.ErrNoRows) {
		return nil, ErrNotFound // 没有行不是数据库故障
	}
	return nil, fmt.Errorf("scan order %s: %w", id, err)
}
if o.Note.Valid {
	fmt.Println(o.Note.String)
}
```

多行查询：

```go
rows, err := db.QueryContext(ctx, `SELECT id, amount_cents FROM orders WHERE status = $1`, "paid")
if err != nil {
	return nil, fmt.Errorf("query orders: %w", err)
}
defer rows.Close() // 即使循环里 return 也要关闭

for rows.Next() {
	var o Order
	if err := rows.Scan(&o.ID, &o.AmountCents); err != nil {
		return nil, fmt.Errorf("scan: %w", err)
	}
	orders = append(orders, o)
}
if err := rows.Err(); err != nil { // 迭代结束后必须检查
	return nil, fmt.Errorf("iterate: %w", err)
}
```

> 边界：`rows.Close()` 要在 `defer` 里，`rows.Err()` 要在循环后检查。提前 `return` 而不关闭 rows 会占住连接，池很快耗尽。

### 4.4 预处理与 SQL 注入

```go
stmt, err := db.PrepareContext(ctx, `INSERT INTO orders(id, amount_cents) VALUES($1, $2)`)
if err != nil {
	return err
}
defer stmt.Close()

for _, o := range orders {
	if _, err := stmt.ExecContext(ctx, o.ID, o.AmountCents); err != nil {
		return fmt.Errorf("insert %s: %w", o.ID, err)
	}
}
```

占位符由驱动处理，不拼字符串：

```go
// 错误：拼接 SQL，注入入口
query := "SELECT * FROM orders WHERE id = '" + id + "'"

// 正确：占位符
query := "SELECT * FROM orders WHERE id = $1" // PostgreSQL
// MySQL 用 ?
```

> 边界：占位符不能用于表名、列名、`ORDER BY` 字段。这些只能来自白名单映射，不能来自请求参数。

### 4.5 事务

```go
tx, err := db.BeginTx(ctx, &sql.TxOptions{
	Isolation: sql.LevelReadCommitted, // 按业务需要选择，不要盲用默认
})
if err != nil {
	return fmt.Errorf("begin: %w", err)
}
defer func() {
	_ = tx.Rollback() // 已 Commit 后 Rollback 返回 ErrTxDone，可安全忽略
}()

if _, err := tx.ExecContext(ctx, `UPDATE accounts SET balance = balance - $1 WHERE id = $2`, amount, from); err != nil {
	return fmt.Errorf("debit: %w", err)
}
if _, err := tx.ExecContext(ctx, `UPDATE accounts SET balance = balance + $1 WHERE id = $2`, amount, to); err != nil {
	return fmt.Errorf("credit: %w", err)
}

if err := tx.Commit(); err != nil {
	return fmt.Errorf("commit: %w", err)
}
```

> 边界：事务里的每条语句都要用 `tx`，混用 `db` 会跑到事务外。事务持有连接，不要在事务里做 HTTP 调用或长时间计算。

### 4.6 批量写入

逐条 `Exec` 往返次数太多，用单条多值 INSERT 或驱动提供的 `CopyFrom`：

```go
// 片段：PostgreSQL 批量插入，占位符按行数生成
placeholders := make([]string, 0, len(orders))
args := make([]any, 0, len(orders)*2)
for i, o := range orders {
	placeholders = append(placeholders, fmt.Sprintf("($%d,$%d)", i*2+1, i*2+2))
	args = append(args, o.ID, o.AmountCents)
}
query := `INSERT INTO orders(id, amount_cents) VALUES ` + strings.Join(placeholders, ",")
_, err := db.ExecContext(ctx, query, args...)
```

> 边界：一条 SQL 的参数个数有上限（PostgreSQL 协议是 65535），分批提交。超大批量用 `COPY`，不要拼一条巨大的 INSERT。

## 五、Redis 客户端与缓存边界

这章解决“缓存客户端怎么配、key 怎么设计、缓存失效怎么办”。Redis 客户端的所有命令都应该带 `context` 和超时。

### 5.1 连接与超时

```go
import "github.com/redis/go-redis/v9"

rdb := redis.NewClient(&redis.Options{
	Addr:         cfg.RedisAddr,     // host:port
	Password:     cfg.RedisPassword, // 空表示无密码
	DB:           0,
	DialTimeout:  2 * time.Second,
	ReadTimeout:  500 * time.Millisecond,
	WriteTimeout: 500 * time.Millisecond,
	PoolSize:     20, // 并发连接上限，按 QPS 估算
})

ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

if err := rdb.Ping(ctx).Err(); err != nil {
	return fmt.Errorf("ping redis: %w", err)
}
```

> 边界：`PoolSize` 不是越大越好，Redis 单线程处理命令，客户端连接过多只会增加上下文切换。默认 10 在多数业务够用。

### 5.2 读写与过期

```go
key := "order:" + id

if err := rdb.Set(ctx, key, data, 10*time.Minute).Err(); err != nil {
	return fmt.Errorf("cache set %s: %w", key, err)
}

val, err := rdb.Get(ctx, key).Bytes()
switch {
case err == nil:
	return val, nil
case errors.Is(err, redis.Nil):
	return nil, ErrCacheMiss // 键不存在是正常分支
default:
	return nil, fmt.Errorf("cache get %s: %w", key, err)
}
```

> 边界：`redis.Nil` 不是错误，必须单独判断。把缓存未命中当故障返回，会让一次正常的冷启动变成 500。

### 5.3 缓存模式与失效

cache-aside 的标准流程：读缓存 → 未命中查库 → 写缓存 → 返回。

```go
func (s *Service) GetOrder(ctx context.Context, id string) (*Order, error) {
	if v, err := s.cache.Get(ctx, id); err == nil {
		return decode(v)
	} else if !errors.Is(err, ErrCacheMiss) {
		s.log.Warn("cache get failed", "err", err) // 缓存故障降级，不阻断主流程
	}

	o, err := s.repo.Find(ctx, id)
	if err != nil {
		return nil, err
	}

	// TTL 加随机抖动，避免同一批 key 同时过期造成击穿
	ttl := 10*time.Minute + time.Duration(rand.IntN(60))*time.Second
	if err := s.cache.Set(ctx, id, encode(o), ttl); err != nil {
		s.log.Warn("cache set failed", "err", err) // 写缓存失败不影响返回
	}
	return o, nil
}
```

| 问题 | 现象 | 处理 |
|---|---|---|
| 缓存穿透 | 查不存在的 key，每次打库 | 空值缓存、布隆过滤器 |
| 缓存击穿 | 热点 key 过期瞬间打库 | 单飞、互斥重建 |
| 缓存雪崩 | 大批 key 同时过期 | TTL 加抖动、多级缓存 |
| 数据不一致 | 更新库后缓存仍旧 | 删除缓存、延迟双删 |

> 边界：先更新数据库再删除缓存，不要“更新缓存”。删除失败要有重试队列；强一致场景不要用缓存，直接读库。

### 5.4 管道与批量

```go
pipe := rdb.Pipeline()
cmds := make([]*redis.StringCmd, 0, len(ids))
for _, id := range ids {
	cmds = append(cmds, pipe.Get(ctx, "order:"+id))
}
if _, err := pipe.Exec(ctx); err != nil && !errors.Is(err, redis.Nil) {
	return nil, fmt.Errorf("pipeline: %w", err)
}

for _, cmd := range cmds {
	v, err := cmd.Result()
	if errors.Is(err, redis.Nil) {
		continue
	}
	// ...
}
```

> 边界：管道只减少网络往返，不保证原子性。需要原子性用 Lua 脚本或 `WATCH/MULTI`，注意脚本执行时间会阻塞整个 Redis。

## 六、组件装配与关闭顺序

这章解决“依赖怎么传、启动顺序怎么排、退出时先关谁”。装配逻辑集中在 `main`，业务包只接收接口。

### 6.1 构造函数返回错误

```go
func NewOrderService(cfg Config, db *sql.DB, cache Cache, log *slog.Logger) *OrderService {
	return &OrderService{cfg: cfg, db: db, cache: cache, log: log} // 依赖全部显式传入
}
```

连接类组件在构造函数里完成“创建 + 首次验证”：

```go
func OpenDB(ctx context.Context, dsn string) (*sql.DB, error) {
	db, err := sql.Open("pgx", dsn)
	if err != nil {
		return nil, fmt.Errorf("open db: %w", err)
	}
	db.SetMaxOpenConns(25)
	if err := db.PingContext(ctx); err != nil {
		db.Close()
		return nil, fmt.Errorf("ping db: %w", err)
	}
	return db, nil
}
```

> 边界：构造失败要释放已创建的资源。`OpenDB` 里 Ping 失败必须 `db.Close()`，否则连接池泄漏。

### 6.2 启动顺序

顺序由依赖方向决定：配置 → 日志 → 数据库/缓存 → 业务服务 → HTTP 服务。


外部依赖不可用时，启动直接失败比“带病启动”好：编排平台会重启，问题暴露在发布阶段而不是流量高峰。

> 边界：强依赖（数据库）失败就退出；弱依赖（推荐服务、埋点）允许降级启动，但要打 `Warn` 并在就绪探针里体现。

### 6.3 优雅退出

```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

srv := &http.Server{
	Addr:              cfg.Addr,
	Handler:           mux,
	ReadHeaderTimeout: 5 * time.Second, // 防慢速请求头攻击
}

go func() {
	if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
		logger.Error("http server", "err", err)
		stop() // 监听失败，触发退出流程
	}
}()

<-ctx.Done()
logger.Info("shutting down")

shutdownCtx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
defer cancel()
if err := srv.Shutdown(shutdownCtx); err != nil {
	logger.Error("shutdown", "err", err)
}

db.Close()  // 先停流量，再关依赖
rdb.Close()
```

关闭顺序与启动相反：停止接收新请求 → 等待在途请求 → 关闭数据库和缓存 → 刷新日志。

| 阶段 | 动作 | 超时 |
|---|---|---|
| 收到信号 | 停止接新连接 | 立即 |
| 在途请求 | `Shutdown` 等待 | 10 到 15 秒 |
| 关闭依赖 | `db.Close`、`rdb.Close` | 立即 |
| 强制退出 | 超过宽限期由编排平台杀 | 30 秒 |

> 边界：`Shutdown` 不会等待 hijacked 连接（WebSocket）。这类服务要自己维护连接注册表，在关闭时逐个通知。

### 6.4 不要在 init 里做 IO

```go
// 错误：init 里连数据库，测试和工具链都被迫连
func init() {
	db, _ = sql.Open("pgx", os.Getenv("DSN"))
}

// 正确：显式调用，错误可处理
func main() {
	db, err := OpenDB(ctx, cfg.DSN)
	if err != nil {
		logger.Error("db", "err", err)
		os.Exit(1)
	}
}
```

> 边界：`init` 只适合注册驱动、设置纯内存默认值。任何网络、文件、环境变量读取都放到 `main`，否则 `go test` 会因为缺少环境而失败。

## 七、最佳实践案例

### 7.1 案例背景

一个网关团队要在发布后 1 分钟内确认所有下游可用。现有做法是手工 `curl` 每个地址，问题是：没有超时，某个地址卡住会拖住整轮；404 和 500 混在一起看；结果没有结构化日志，发布记录里贴不出证据。

目标与约束：

- 从 JSON 文件读服务和检查目标，环境变量可覆盖超时；
- 每个目标并发检查，单次请求有超时，失败按配置重试；
- 4xx 不重试，5xx 和连接错误重试；
- 输出按名称排序的表格，同时用 `slog` 输出 JSON 日志；
- 任一目标失败，进程退出码为 1；
- 支持 Ctrl+C 取消。

示例配置 `config.json`：

```json
{
  "service": "gateway",
  "timeout_ms": 1500,
  "targets": [
    {"name": "home", "url": "http://127.0.0.1:8000/", "retries": 1},
    {"name": "missing", "url": "http://127.0.0.1:8000/missing", "retries": 1},
    {"name": "api", "url": "http://127.0.0.1:8000/api/orders", "retries": 2}
  ]
}
```

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"flag"
	"fmt"
	"io"
	"log/slog"
	"math/rand/v2"
	"net/http"
	"os"
	"os/signal"
	"sort"
	"strconv"
	"sync"
	"syscall"
	"text/tabwriter"
	"time"
)

type Target struct {
	Name    string `json:"name"`
	URL     string `json:"url"`
	Retries int    `json:"retries"`
}

type Config struct {
	Service   string   `json:"service"`
	TimeoutMS int      `json:"timeout_ms"`
	Targets   []Target `json:"targets"`
}

// Timeout 把毫秒配置转成 Duration，调用方不用关心单位。
func (c Config) Timeout() time.Duration {
	return time.Duration(c.TimeoutMS) * time.Millisecond
}

func (c *Config) applyDefaults() {
	if c.Service == "" {
		c.Service = "unknown"
	}
	if c.TimeoutMS == 0 {
		c.TimeoutMS = 1000
	}
	for i := range c.Targets {
		if c.Targets[i].Retries < 0 {
			c.Targets[i].Retries = 0
		}
	}
}

func (c Config) validate() error {
	var errs []error
	if c.TimeoutMS <= 0 || c.TimeoutMS > 60_000 {
		errs = append(errs, fmt.Errorf("timeout_ms %d out of range", c.TimeoutMS))
	}
	if len(c.Targets) == 0 {
		errs = append(errs, errors.New("targets is empty"))
	}
	for i, t := range c.Targets {
		if t.Name == "" || t.URL == "" {
			errs = append(errs, fmt.Errorf("targets[%d]: name and url are required", i))
		}
	}
	return errors.Join(errs...)
}

// LoadConfig 顺序：文件 → 默认值 → 环境变量 → 校验。
func LoadConfig(path string) (*Config, error) {
	f, err := os.Open(path)
	if err != nil {
		return nil, fmt.Errorf("open config %s: %w", path, err)
	}
	defer f.Close()

	dec := json.NewDecoder(io.LimitReader(f, 1<<20))
	dec.DisallowUnknownFields() // 配置拼错要立刻失败
	var cfg Config
	if err := dec.Decode(&cfg); err != nil {
		return nil, fmt.Errorf("decode config %s: %w", path, err)
	}

	cfg.applyDefaults()

	// 环境变量覆盖，便于容器里改超时而不改镜像
	if v, ok := os.LookupEnv("HEALTH_TIMEOUT_MS"); ok {
		n, err := strconv.Atoi(v)
		if err != nil {
			return nil, fmt.Errorf("HEALTH_TIMEOUT_MS=%q: %w", v, err)
		}
		cfg.TimeoutMS = n
	}
	if err := cfg.validate(); err != nil {
		return nil, fmt.Errorf("invalid config: %w", err)
	}
	return &cfg, nil
}

type Result struct {
	Name    string
	URL     string
	Status  int
	Latency time.Duration
	Err     error
}

// check 对单个目标执行带重试的 GET；4xx 直接返回，5xx 与连接错误重试。
func check(ctx context.Context, client *http.Client, t Target) Result {
	start := time.Now()
	var (
		lastErr    error
		lastStatus int
	)

	for attempt := 0; attempt <= t.Retries; attempt++ {
		if attempt > 0 {
			// 退避加抖动：避免同一批目标同时重试，把下游打得更惨
			delay := time.Duration(attempt*attempt)*100*time.Millisecond +
				time.Duration(rand.IntN(50))*time.Millisecond
			select {
			case <-time.After(delay):
			case <-ctx.Done():
				return Result{Name: t.Name, URL: t.URL, Latency: time.Since(start), Err: ctx.Err()}
			}
		}

		req, err := http.NewRequestWithContext(ctx, http.MethodGet, t.URL, nil)
		if err != nil {
			return Result{Name: t.Name, URL: t.URL, Latency: time.Since(start),
				Err: fmt.Errorf("build request: %w", err)}
		}

		resp, err := client.Do(req)
		if err != nil {
			lastErr = fmt.Errorf("request: %w", err)
			continue
		}

		// 读掉小段 body 再关闭，连接可以放回池里复用
		_, _ = io.Copy(io.Discard, io.LimitReader(resp.Body, 4<<10))
		resp.Body.Close()
		lastStatus = resp.StatusCode

		if resp.StatusCode >= 200 && resp.StatusCode < 300 {
			return Result{Name: t.Name, URL: t.URL, Status: resp.StatusCode, Latency: time.Since(start)}
		}
		if resp.StatusCode < 500 && resp.StatusCode != http.StatusTooManyRequests {
			// 4xx 是确定性失败，重试没有意义
			return Result{Name: t.Name, URL: t.URL, Status: resp.StatusCode, Latency: time.Since(start),
				Err: fmt.Errorf("status %d", resp.StatusCode)}
		}
		lastErr = fmt.Errorf("status %d", resp.StatusCode)
	}

	return Result{Name: t.Name, URL: t.URL, Status: lastStatus,
		Latency: time.Since(start), Err: lastErr}
}

func main() {
	configPath := flag.String("config", "config.json", "配置文件路径")
	flag.Parse()

	logger := slog.New(slog.NewJSONHandler(os.Stderr, &slog.HandlerOptions{
		Level: slog.LevelInfo,
		ReplaceAttr: func(groups []string, a slog.Attr) slog.Attr {
			if a.Key == slog.TimeKey {
				return slog.String("ts", a.Value.Time().Format(time.RFC3339))
			}
			return a
		},
	}))

	if err := run(*configPath, logger); err != nil {
		logger.Error("healthcheck failed", "err", err)
		os.Exit(1)
	}
}

func run(configPath string, logger *slog.Logger) error {
	cfg, err := LoadConfig(configPath)
	if err != nil {
		return err
	}

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	client := &http.Client{
		Timeout: cfg.Timeout(), // 单次请求上限
		Transport: &http.Transport{
			Proxy:               http.ProxyFromEnvironment,
			MaxIdleConns:        50,
			MaxIdleConnsPerHost: 10,
			IdleConnTimeout:     30 * time.Second,
		},
	}

	// 结果通道 + WaitGroup：并发执行，单 goroutine 收集，不需要锁
	results := make(chan Result, len(cfg.Targets))
	var wg sync.WaitGroup
	wg.Add(len(cfg.Targets))
	for _, t := range cfg.Targets {
		go func(t Target) {
			defer wg.Done()
			r := check(ctx, client, t)
			if r.Err != nil {
				logger.Error("target failed", "name", r.Name, "url", r.URL,
					"status", r.Status, "err", r.Err)
			} else {
				logger.Info("target ok", "name", r.Name, "url", r.URL,
					"status", r.Status, "latency_ms", r.Latency.Milliseconds())
			}
			results <- r
		}(t)
	}
	wg.Wait()
	close(results)

	out := make([]Result, 0, len(cfg.Targets))
	for r := range results {
		out = append(out, r)
	}
	sort.Slice(out, func(i, j int) bool { return out[i].Name < out[j].Name })

	tw := tabwriter.NewWriter(os.Stdout, 0, 4, 2, ' ', 0)
	fmt.Fprintln(tw, "NAME\tURL\tSTATUS\tLATENCY")
	failed := 0
	for _, r := range out {
		status := "-"
		if r.Status != 0 {
			status = strconv.Itoa(r.Status)
		}
		fmt.Fprintf(tw, "%s\t%s\t%s\t%s\n", r.Name, r.URL, status, r.Latency.Round(time.Millisecond))
		if r.Err != nil {
			failed++
		}
	}
	if err := tw.Flush(); err != nil {
		return fmt.Errorf("write report: %w", err)
	}

	if failed > 0 {
		return fmt.Errorf("%d of %d targets failed", failed, len(out))
	}
	return nil
}
```

```go
func TestCheckDoesNotRetry4xx(t *testing.T) {
	var hits atomic.Int32
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		hits.Add(1)
		w.WriteHeader(http.StatusNotFound)
	}))
	defer srv.Close()

	client := &http.Client{Timeout: time.Second}
	r := check(context.Background(), client, Target{Name: "t", URL: srv.URL, Retries: 3})
	if r.Err == nil {
		t.Fatal("want error for 404")
	}
	if got := hits.Load(); got != 1 {
		t.Fatalf("server hits = %d, want 1 (4xx must not retry)", got)
	}
}
```

示例里 `api` 和 `missing` 都返回 404，属于确定性失败，不重试直接判定；`home` 返回 200。两条 stderr 日志是 JSON，采集端可以直接按 `name` 聚合。

用环境变量覆盖超时：

```bash
HEALTH_TIMEOUT_MS=200 go run . -config config.json
```

```bash

echo "exit=$?"
```

```text

```

### 7.3 案例结果

三个目标并发检查，总耗时接近最慢的一次请求而不是三次之和；200 的目标通过，两个 404 的目标失败，退出码 1，发布流水线据此阻断。日志是 JSON，表格可直接贴进发布记录，配置里的超时可以由环境变量覆盖，不需要重新构建镜像。

| 指标 | 手工 curl | 本工具 |
|---|---|---|
| 单目标超时 | 无 | 1.5 秒 |
| 并发 | 串行 | 并发 |
| 4xx 重试 | 无概念 | 明确不重试 |
| 输出 | 人眼看终端 | 表格 + JSON 日志 |
| 流水线集成 | 无 | 退出码 1 |

失败模式与复盘：

- 最初 `http.Get` 用默认客户端，某个目标挂起导致整轮不结束；改成自建 `http.Client`，`Timeout` 和 `ResponseHeaderTimeout` 都设上限；
- 重试没有区分状态码，404 被重试 3 次，日志里出现三条相同失败；补了“4xx 直接返回”；
- 重试没有退避，下游刚重启就被三倍流量打满；改为指数退避加随机抖动；
- `resp.Body` 没有关闭，压测时连接数持续上涨；统一在状态判断前 `io.Copy(io.Discard, io.LimitReader(...))` 再 `Close`；
- 结果直接由多个 goroutine 写共享切片，`-race` 报警；改为带缓冲的 channel，主 goroutine 单点收集；
- 日志里的“target ok”把 404 也写成成功，误导排查；日志措辞改为按 `Err` 区分，状态码单独成字段；
- 配置字段拼错（`timeout_ms` 写成 `timeout`）时被静默忽略；`DisallowUnknownFields` 让启动直接失败。
