# 全栈项目 · 内容导读

这个栏目放的是**完整走完一条交付链的实战项目**：需求怎么定、原型怎么出、架构怎么切、代码怎么写、怎么测、怎么上线、审查挑出了什么。

**每个项目里的文档就是这个项目交付过程本身的产物**：同一套内容在仓库的 `docs/` 里，站点里看到的是镜像，两边不会有两种说法。

## 一、有哪些项目

| 项目 | 主要做什么 | 链路 |
| --- | --- | --- |
| **[01-米奇妙妙屋](./01-米奇妙妙屋/)** | 一个个人全栈知识库站点：219 篇技术笔记 + 7 份 Agent 工作流文档，纯静态发布，无后端无数据库，推一次代码自动上线 | 产品 / 设计 / 架构 / 开发 / 测试 / 运维 / 审查，七个角色齐全 |

**目前只有这一个完整项目。** 后续每做完一个项目，就按同样的结构追加一个目录——栏目结构不变，只增加数据。

## 二、每个项目里有什么

一个项目一个目录，下分七个角色：

| 目录 | 里面放什么 |
| --- | --- |
| `00-项目介绍` | 单篇。项目怎么来的、走过哪些弯路、每个页面的实测尺寸、文档怎么读 |
| `01-产品` | PRD、产品术语表 |
| `02-设计` | 设计系统、页面规格、可交互原型 |
| `03-架构` | 系统架构、架构图示、关键决策（ADR）、项目环境规范 |
| `04-开发` | 代码规范、技术方案、实现记录 |
| `05-测试` | 测试策略、测试方案、测试报告 |
| `06-运维` | 服务详细情况、部署拓扑、运维手册、发布记录 |
| `07-审查` | 审查清单、审查报告 |

**这些笔记是 `docs/` 的镜像，不是手抄。** 跑 `npm run sync:project` 从 `docs/` 生成；改内容去改 `docs/`，这里跟着变。只有 `00-项目介绍` 是手写的——它讲的东西不属于任何一个角色的产物，也不该在。

三个 HTML 产物（可交互原型、架构图示、部署拓扑）用 iframe 内嵌，可以在页面上直接操作，不是截图。

## 三、阅读顺序

**第一次读某个项目，从 `00-项目介绍` 开始，然后按序号从左到右。** 这个顺序就是实际的推进顺序：

```text
00-项目介绍   ← 先看这个：为什么做、怎么做的、哪些地方返工过、界面尺寸
01-产品       ← 需求怎么定的，验收标准是什么
02-设计       ← 长什么样，页面上每个元素多大、什么色
03-架构       ← 技术上怎么搭，模块怎么切，三个关键决策的取舍
04-开发       ← 怎么实现的，脚本怎么写的
05-测试       ← 怎么证明做对了
06-运维       ← 怎么上线的，出问题怎么回滚
07-审查       ← 独立审查挑出了什么问题，怎么修的
```

按目的选读法：

| 想干什么 | 读哪几篇 |
| --- | --- |
| 只想看结果 | `00-项目介绍` 的「结论」一节 + `05-测试/03-测试报告` 的「裁决」一节 |
| 想看一个东西怎么从零推到上线 | 从 `01-产品` 顺着读到底，七篇连起来就是一条完整交付链 |
| 想抄做法 | 直接跳 `04-开发/02-技术方案` 与 `03-实现记录`，那里有能跑的代码与踩过的坑 |
| 想抄界面 | 先看 `02-设计/02-原型图` 的可交互原型，再对 `03-页面规格` 里的实测尺寸 |

## 四、为什么有些序号是缺的

你会看到跳号，比如 `01-产品` 从 `03-` 开始、`03-架构` 从 `01` 跳到 `04`。

**这不是项目不完整，是这些产物对这个项目结构上不存在。** 工作流模板规定了每个角色的标准序号，但模板是按「有后端、有数据库、有外部系统」的项目写的。像米奇妙妙屋这样的纯静态站点，下面这些位置没有东西可写：

| 序号 | 模板里是什么 | 为什么不需要 |
| --- | --- | --- |
| `01-产品/01-BRD` | 商业需求 | 个人站点，没有商业投入与回报 |
| `01-产品/02-MRD` | 市场需求 | 无外部市场，读者就是作者自己 |
| `03-架构/03-状态机` | 每个带 `status` 列的实体一张图 | 没有订单、工单、用户这类实体 |
| `03-架构/05-数据库设计` | 表结构、枚举、迁移 | 无数据库，内容是 Git 仓库里的 Markdown |
| `03-架构/06-ER图` | 表关系图 | 同上，无表可画 |

**判断标准很简单：这个产物回答的问题，本项目存不存在。** BRD 回答「投多少、赚多少」，MRD 回答「谁有这个问题」，ER 图回答「表和表怎么关联」——这三个问题在这个项目里都不成立，所以跳过。

**每个项目都会在自己的 `00-项目介绍` 里，把「缺哪些序号、为什么不需要」逐条列出来。** 跳号在那边有解释，不用猜，也不代表项目做少了东西。

## 五、这套结构能复用到别的项目吗

能，而且后续项目就是这么打算的：

| 层 | 是否随项目变 |
| --- | --- |
| 栏目结构（`00-内容导读` + `NN-项目名` + 七个角色） | 不变 |
| 各角色下的文档清单 | 按项目裁剪（缺号规则同上） |
| `00-项目介绍` 的写法 | 不变：来龙去脉 + 返工记录 + 界面走查 + 怎么读 |

**结构固定带来的好处**：读到第二个项目时，你已经知道去哪找需求、去哪找测试结果、去哪找审查结论，不用重新学一遍栏目的组织方式。
