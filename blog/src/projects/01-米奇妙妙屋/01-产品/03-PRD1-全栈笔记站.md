# 米奇妙妙屋 · 全栈笔记站

## 一、背景与目标

### 1.1 背景

技术笔记散在本地，按 `00-` 到 `09-` 的方向分好目录，但只能在编辑器里翻：手机上打不开，也发不出去。

想做的事很直接——**把这些笔记变成一个能看的网站**。不是按时间流的博客，是能按方向逐层往下钻的知识库。

参考对象是 [vuepress-theme-hope 官方文档](https://theme-hope.vuejs.press/zh/)。它已经提供文档型布局、左侧目录树、右侧本页目录、全文搜索、深浅色切换，正好是知识库要的东西，所以不自研主题。

### 1.2 目标

| # | 目标 | 数字 | 怎么验证 |
|---|---|---|---|
| 1 | 五个栏目都能访问，且都有实质内容或明确结构 | 5 个栏目，0 个空白页 | 逐个点开 |
| 2 | 笔记能按「方向 → 章节 → 篇」三层往下钻 | 一层不缺 | 从首页点到任意一篇，路径不断 |
| 3 | 首页能让人一眼看懂这是什么站 | 标题 + 一句定位 + 方向入口 | 自己看 |
| 4 | 站点不像模板默认样式 | 有自定义配色与首页视觉 | 自己看 |
| 5 | 手机能读 | 320px 起不横向滚动 | 手机开一次 |

第 4 条是主观的，所以不写成验收标准，写成设计约束——「好看」机器判不了，只能人拍板。

### 1.3 五个栏目怎么来的

最初就想要这五个，按「读 → 用 → 怎么读」排：

| 栏目 | 解决什么 | 为什么是它 |
|---|---|---|
| **全栈笔记** | 知识本体：十个方向的技术笔记 | 站点主体，占九成篇幅 |
| **全栈项目** | 从需求到上线的完整实战 | 只读笔记不会做项目 |
| **Agent工作流** | 一人 + 多个 AI 的交付规范 | 开发方式变了，流程得写下来 |
| **优质资源** | 外部文档、工具、开源项目 | 别人的东西不抄进笔记，但要找得到 |
| **学习方法** | 学习金字塔、布鲁姆层级这类认知模型 | 决定怎么读，不是读什么 |

**五个栏目有先后关系，不是并列的五个列表。** 首页正文把这层关系写清楚了：先按方向读懂机制，再跟着项目做一遍，用工作流约束 AI 的输出，靠学习方法决定读的顺序，外部资源作补充。

**首页入口拆成 12 张卡片**：五个栏目里「全栈笔记」是模块不是单页，按十个方向各给一张卡；「优质资源」「学习方法」各一张。所以卡片数 = 10 + 2，不是 5。

## 二、范围

从「空仓库」到「站点能上线」：骨架、五个栏目的结构与入口、首页视觉、内容接入方式。

**结束线**：五栏目可访问、笔记三层可下钻、首页有介绍与配色、`npm run build` 出产物、推 GitHub 自动发布。

## 三、非目标

| 不做的事 | 为什么 | 什么时候可能做 |
|---|---|---|
| 站点内编辑笔记 | 内容在独立仓库，站点只读 | 不做，这是架构选择 |
| 评论、点赞、登录 | 纯静态没有后端，加这些就得建服务 | 有真实互动需求时 |
| 自研主题 | 官方主题已覆盖目录树、搜索、深浅色、SEO | 主题满足不了硬需求时 |
| 语义搜索 / 向量检索 | 几百篇的量级，全文搜索够用 | 篇数上千再评估 |
| 学习方法 8 篇正文 | 本期只定结构与入口 | 下一期 |
| 铺开多个实战项目 | 本期只放第一个完整项目 | 第二个项目做完时 |
| 压缩存量截图 | 不是本期问题 | 产物体积吃紧时 |

## 四、用户故事

> 作为**作者**，我想让本地笔记仓库直接变成站点内容、不用手工搬文件，以便加笔记只在源库写。

> 作为**作者**，我想首页能一眼说清这站是什么，以便发给别人时不用解释。

> 作为**读者**，我想从首页点方向、再点章节、再点一篇，一路不用回退，以便快速找到想看的那篇。

> 作为**读者**，我想导航里有五个栏目而不是一堆零散页面，以便知道除了笔记还有什么。

> 作为**读者**，我想手机上也能读，以便通勤时看。

## 五、业务规则

### 5.1 规则清单

| 编号 | 规则 |
|---|---|
| R-01 | 导航固定六项，顺序：首页 / 全栈笔记 / 全栈项目 / Agent工作流 / 优质资源 / 学习方法 |
| R-02 | 笔记按「方向 → 章节 → 篇」组织，方向用 `00-` 到 `09-` 两位数字前缀，排序靠它 |
| R-03 | 侧边栏由磁盘目录生成，不手写；新增笔记不改配置 |
| R-04 | 站点只读源库，内容不在站点内编辑 |
| R-05 | 默认浅色，只有手动点开关才切深色，不跟随系统 |
| R-06 | 每个栏目都要有落地页面，不留空链接 |
| R-07 | 站点标题、描述、作者、页脚四处文案一致 |

### 5.2 状态流转

**不适用。** 没有带状态字段的业务实体。

### 5.3 字段规则

**不适用。** 无表单、无用户输入。

唯一需要约束的是笔记的 frontmatter：

| 字段 | 必填 | 来源 | 说明 |
|---|---|---|---|
| `title` | 是 | 正文第一行 H1 | 页面标题用它 |
| `category` | 是 | 所在方向目录名 | 用于归档展示 |
| `date` | 否 | 不填 | 笔记不按时间流组织，RSS 用构建时间 |

**源库是纯 Markdown，不写 frontmatter。** 这三项由同步环节补（见 TD1）。

## 七、依赖与约束

| 类型 | 内容 |
|---|---|
| 外部系统 | GitHub、Cloudflare Pages |
| 技术选型 | VuePress 2 + vuepress-theme-hope 2。理由：目录树、搜索、深浅色、SEO 已覆盖，自研不划算 |
| 内容来源 | 两个独立仓库：全栈笔记、Agent 工作流。站点只读 |
| 数据 | 无数据库，内容即数据 |
| 时间 | 无硬约束 |
| 体积 | Cloudflare 上限 20,000 文件 / 单文件 25 MiB |
| 合规 | 内容 CC BY-NC-SA 4.0 |
