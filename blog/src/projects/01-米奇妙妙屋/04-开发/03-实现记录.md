## 二、关键实现

### 2.1 起站：三件套

```text
config.ts → 构建层（语言、标题、head 注入、Vite）
theme.ts  → 展示层（导航、侧栏、插件）
index.md  → 首页（home: true）
```

**分两个文件是刻意的**：以后换主题只动 `theme.ts`，`config.ts` 基本不动。

`config.ts` 里唯一不常规的是 `head` 注入的那段浅色脚本，以及 Vite 的两个配置：

```ts
ssr: { noExternal: ["@vuepress/search-helper", "@vuepress/plugin-slimsearch"] },
optimizeDeps: { include: ["mermaid", "dayjs"] },
```

- 第一条：搜索插件的客户端模块带 CSS 副作用导入，被 SSR 外部化时 Node 会以 `.css` 模块加载而报错
- 第二条：mermaid v12 依赖 dayjs 的 UMD 包，预打包才能拿到正确的 default 导出

**两条都是踩了才加上的，不写会构建失败。**

### 2.2 侧边栏：一个递归函数解决三层

```ts
const readDir = (dir: string): SidebarArrayOptions => {
  const items: SidebarArrayOptions = [];
  const sorted = fs.readdirSync(dir, { withFileTypes: true })
    .filter((e) => !e.name.startsWith(".") && e.name !== "assets")
    .sort((a, b) => {
      if (a.isDirectory() !== b.isDirectory()) return a.isDirectory() ? 1 : -1;
      return a.name.localeCompare(b.name, "zh-CN", { numeric: true });
    });

  for (const entry of sorted) {
    if (entry.isDirectory()) {
      items.push({
        text: entry.name,
        prefix: `${entry.name}/`,
        collapsible: true,
        children: readDir(path.join(dir, entry.name)),
      });
    } else if (entry.name.endsWith(".md") && entry.name !== "index.md") {
      items.push({ text: entry.name.replace(/\.md$/, ""), link: entry.name.replace(/\.md$/, "") });
    }
  }
  return items;
};
```

**`prefix` 是主题的机制**：子项链接只需写相对文件名，主题会自动拼上前缀。所以递归时每一层只负责自己的相对名，不拼完整路径。

**排序那条要特别说明**：`localeCompare(name, "zh-CN", { numeric: true })` 里的 `numeric` 不能省。不加的话 `10-` 会排在 `2-` 前面（字典序），10 个方向里 `09-大模型` 会跑到 `01-` 前面。

**文件优先于目录**：`00-内容导读`（文件）要排在 `00-计算机基础`（目录）之前。不加这条，导读会被挤到 10 个方向后面——页能访问但入口消失，最难发现。

### 2.3 首页视觉：三个作用域

| 作用域 | 做了什么 |
|---|---|
| `.home-aurora` | 整页背景：2rem 网格 + 三团径向渐变，`background-attachment: fixed` |
| `.vp-hero-title` | 主标题渐变（覆盖主题的 `--vp-c-accent` 渐变） |
| `.vp-feature-item` | 玻璃卡片：`rgba(255,255,255,.62)` + `backdrop-filter: blur(8px)` + 描边阴影 |

**`#main-description` 也加了渐变**，而且必须写两个选择器：

```scss
.vp-hero-description,
#main-description { … }
```

因为主题在窄屏用前者、宽屏用后者。只写一个会在某个宽度失效——这条是实测发现的。

**卡片间距用 `margin: .5rem` 而不是 `gap`**：主题的 `.vp-features` 是 `flex` + `flex-wrap: wrap`，用 `gap` 会在换行时出现不均匀的边距。

### 2.4 同步：三种修补的实际代码

**去 H1 编号**（只匹两位数字，不碰 `# 01-01-`）：

```js
const stripHeadingNumber = (text) =>
  text.replace(/^# ([0-9]{2})-(?!\d)(.+)$/m, "# $2");
```

**保护 <span v-pre>`${{ }}`</span>**（围栏内跳过，只包行内代码）：

```js
lines[i] = line.replace(/`[^`\n]*`/g, (span) =>
  span.includes("{{") ? `<span v-pre>${span}</span>` : span,
);
```

**改名 `C++`**（在复制每一步做，不在事后 `mv`）：

```js
const renameName = (name) =>
  RENAMES.reduce((acc, [from, to]) => acc.split(from).join(to), name);
```

**为什么改名必须在复制时做**：`05-后端/04-C++/01-C++语法/01-C++基本语法.md` 一共 4 处含 `C++`。事后 `mv` 要再遍历一遍，深层目录容易漏。

### 2.5 目录页：表格而不是列表

第一版是缩进列表：

```text
- 00-计算机基础 · 34 篇
  - 01-数据结构 · 8 篇
```

问题：想找某一篇得逐级点，看不到篇名。改成表格：

```text
| 方向 | 篇数 | 章节 | 覆盖 |
| 章节 | 篇数 | 篇目 |      ← 篇名全做成链接，· 分隔
```

**三层方向的判断**：

```js
const isThreeLevel = chapters.some((c) => childDirs(join(sectionDir, c)).length > 0);
```

三层方向（`05-后端`）输出「语言 + 分类」两级表，两层方向输出单张「章节 + 篇目」表。

### 2.6 深浅色：首屏脚本

```js
try {
  var k = "vuepress-theme-hope-scheme", s = localStorage.getItem(k);
  if (s !== "dark") {
    if (s !== "light") localStorage.setItem(k, "light");
    document.documentElement.setAttribute("data-theme", "light");
  }
} catch (e) {}
```

**三个动作缺一不可**：保存设置（下次进来还是浅色）、设 `data-theme`（首屏就是浅色）、等用户手动切深色才跳过。

只设 `data-theme` 不保存设置，刷新后会回到系统色；只保存不设 `data-theme`，首屏仍会闪。
