# 代码规范

> **最后更新**：2026-11-22

**这份不设门**——它是长期约定，不是某条需求的产物。

## 一、仓库与目录

这不是一个「前端 + 后端」项目，**套用模板的三层 `src/frontend`、`src/backend` 会造出空目录**。本项目的分层是：

```text
studynotes/
├─ blog/                      # 唯一有代码的地方
│  ├─ scripts/                # 两个 Node 脚本，纯 ESM
│  │  ├─ sync-content.mjs     # 同步：源库 → src/notes、src/workflow、docs/99-模板文档
│  │  └─ gen-notes-index.mjs  # 生成 /notes/ 目录页
│  ├─ src/
│  │  ├─ .vuepress/           # 站点配置层：config/theme/navbar/sidebar/styles
│  │  ├─ index.md             # 首页
│  │  ├─ notes/               # 同步产物，勿手改
│  │  ├─ workflow/            # 同步产物，勿手改
│  │  ├─ methods/             # 手写内容：目录 + 8 个模型入口
│  │  ├─ projects/            # 00-内容导读与项目介绍手写，七个角色目录由 sync:project 生成
│  │  └─ resources/           # 手写内容：分类表 + 收录规则
│  ├─ package.json
│  └─ wrangler.jsonc          # 备用 Workers 部署配置
├─ docs/                      # 项目文档（本目录）
└─ 根文件：README.md / AGENTS.md / .gitignore
```

| 层 | 负责 | 不负责 |
|---|---|---|
| `scripts/` | 数据搬运与格式修补 | 不管怎么渲染 |
| `.vuepress/` | 路由、侧栏、主题、样式 | 不读写内容文件 |
| `src/**/*.md` | 内容本身 | 不含逻辑 |
| `docs/` | 过程文档 | **不发布到站点** |

**模块边界**：`scripts/` 只写文件、不 import 任何 `.vuepress/` 里的模块；`.vuepress/` 只读磁盘，不调用 `scripts/` 的函数。两者通过「约定好的目录结构」通信，不通过代码耦合。

## 二、Git 初始化与身份

**新机器第一次提交前必须配这三项：**

```bash
git config --global user.name  "真实姓名"
git config --global user.email "真实邮箱"
git config --global init.defaultBranch dev
```

| 项 | 要求 | 为什么 |
|---|---|---|
| `user.name` | 真实姓名 | 出问题能追到人 |
| `user.email` | 常用邮箱 | 不用临时邮箱，避免失联 |
| 机器人身份 | 禁止 | `ai-bot@…` 这类身份等于无法追责 |

**AI 用当前开发者身份提交。** 责任归让 AI 干活的人，不另造机器人账号。

**克隆时必须确认分支：**

```bash
git clone -b dev <仓库地址>
git branch --show-current   # 必须是 dev
```

**本项目的分支实况与规范有偏差，需要说明：**

| 项 | 规范要求 | 本项目现状 |
|---|---|---|
| 默认分支 | `dev` | 单一主线 `master`（本地检出为 `main`，与远端同名分支一致） |
| 分支模型 | `dev` → `test` → `prod` | **只有一条主线**。站点是个人站，没有测试环境，`test`/`prod` 分离没有收益 |
| 发布 | 人合并到 `prod` | 推 `master`/`main` 即由 Cloudflare 自动构建发布 |

**这是有意选择的主线模型。** 三段分支的规范是为多人协作的团队项目写的；这个仓库只有一个人、没有测试集群，`dev → test → prod` 三段没有可隔离的东西，加分支只增加同步成本。发布由 Cloudflare 从单一主线构建，回滚走历史部署，不需要第二套分支。

## 三、分支模型

### 3.1 本项目实际用几条

| 分支 | 用途 | 谁推 |
|---|---|---|
| `main`（本地）/ `master`（远端） | 唯一主线，推上去即部署 | 站点作者 |

**就这一条。** 需要试新样式时用短期分支，验证完即删，不合并不复用。

### 3.2 各分支推什么

| 分支 | 推什么 | 为什么 |
|---|---|---|
| 主线 | 全部：`blog/`、`docs/`、根文件 | 发布即全量，没有裁剪需求 |
| `docs/99-tmp/` | **永不入库**（已在 `.gitignore`） | 临时区，见第六节 |

## 四、提交信息

格式：`类型: 说明`

```text
feat: 接入全栈笔记 v3
fix: 修正 C++ 目录改名后目录页 404
docs: 补 PRD1 与页面规格
style: 首页 tagline 改为渐变
chore: 加 sync 脚本到 npm scripts
```

| 类型 | 什么时候用 |
|---|---|
| `feat` | 新增栏目、新增脚本、新增内容区 |
| `fix` | 修断链、修构建错、修样式错位 |
| `docs` | 只改 `docs/` 或 `README.md` / `AGENTS.md` |
| `style` | 只改样式，不改行为 |
| `chore` | 依赖、脚本、配置 |

**一次提交只做一类事。** 内容同步产物与样式改动分开提交，回滚时才能只退一半。

**必须写清「为什么」而不只是「改了什么」**：`fix: C++ 改名 Cpp` 不够，要写 `fix: C++ 改名 Cpp，否则构建后目录变 04-C__，目录页那条链接 404`。

## 五、命名

| 对象 | 规则 | 例子 |
|---|---|---|
| 笔记目录 | `NN-中文名`，两位数字前缀，**不能去** | `00-计算机基础`、`05-后端` |
| 笔记文件 | `NN-标题.md` | `01-绪论.md`、`02-SpringBoot应用框架.md` |
| 脚本 | kebab-case 动词短语 | `sync-content.mjs`、`gen-notes-index.mjs` |
| 配置 | 单个名词，走主题约定 | `config.ts`、`theme.ts`、`navbar.ts` |
| CSS 变量 | 用主题的 `--vp-c-*`，不自造 | `--vp-c-accent` |
| 手写 SCSS 类 | 只在首页作用域内，前缀 `home-` | `.home-aurora` |

**笔记文件的数字前缀是排序依据**，`sidebar.ts` 与 `gen-notes-index.mjs` 都靠它排序。改名等于改顺序。

**路径里不能出现的字符：**

| 字符 | 为什么 | 处理 |
|---|---|---|
| `+` | VuePress 转义成 `_`，产物目录变 `04-C__` | 同步器把 `C++` 改成 `Cpp` |
| `#`、`?` | URL 分隔符 | 不用 |
| 空格 | 链接里要编码，易碎 | 已存在的两处（`07-Spring Boot.md`、`02-Android Jetpack Compose与工程化.md`）保留，因为源库同名 |

## 六、目录与文件禁令

| 禁令 | 为什么 |
|---|---|
| 手改 `blog/src/notes/` 与 `blog/src/workflow/` | 同步产物，下次 sync 全被覆盖 |
| 手改 `blog/src/notes/index.md` | 由脚本生成 |
| 提交 `blog/node_modules` / `dist` / `.cache` / `.temp` | 已在 `.gitignore` |
| 提交 `docs/99-tmp/` | 临时区，工作流明确要求不入库 |
| 提交 `.DS_Store` / `.openchamber/` | 本地产物 |
| 手改 `docs/99-模板文档/` | 同步产物，改源仓库 |
| 在 `docs/` 之外新建项目文档 | 文档只有一处 |
| 用 `git stash` 切分支 | 单人也能丢改动，且 AI 并发时会 stash 掉别人的 |
| 削弱断言让构建"通过" | 本项目无测试断言，但同理禁止改校验脚本绕开断链 |

**每条都对应一次真实踩过的坑**，新加一条时注明日期与原因。
