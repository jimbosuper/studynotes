# 测试策略

> **最后更新**：2026-11-22

**这份不设门**——它是长期约定，不随需求改。真正的门在 `02-测试方案/TP`（门 5）。

## 一、测什么、不测什么

| 覆盖 | 说明 |
|---|---|
| 构建完整性 | 365 页全部渲染，退出码 0 |
| 站内链接 | 全部 `href` 可解析到产物文件或目录索引 |
| 图片引用 | 正文引用的图片文件真实存在 |
| 内容同步 | 源库 → 站点的篇数与目录结构一致 |
| 目录页结构 | `/notes/` 的表格与磁盘目录同构（含三层方向） |
| 侧边栏顺序 | `00-内容导读` 在 10 个方向之前；工作流 7 项顺序固定 |
| 首页与导航 | 6 个导航项、3 个按钮、12 张卡片的文字与链接 |
| 深浅色 | 默认浅色；手动切换后渐变标题与卡片背景正确 |
| 手机宽度 | ≤720px 时侧栏与右目录隐藏、卡片单列 |

| 不测 | 原因 | 风险谁承担 |
|---|---|---|
| 单元测试 | 站点没有业务逻辑，只有两个文件搬运脚本。写单元测试等于「测试 `fs.copyFileSync` 能复制文件」 | 站点作者，接受。脚本出错的表现是构建失败或页数不对，能立即看到 |
| 组件/E2E 自动化 | 无测试框架（无 vitest / playwright），引入成本高于收益 | 站点作者，接受。页面结构由 VuePress 主题保证，改的是配置不是组件 |
| 浏览器兼容 | 只覆盖现代浏览器（Chrome / Safari / Edge 近两年版本） | 读者，README 未承诺旧浏览器支持 |
| 性能基准 | 静态直出，无运行时计算 | 站点作者。已知瓶颈是图片体积，记在架构文档 |
| 内容正确性 | 笔记里的技术结论对不对，属于内容源仓库的职责 | 内容作者 |
| 搜索召回质量 | slimsearch 的排序与召回由插件决定 | 站点作者，接受 |

**每条排除都写了风险归属。** 不接受风险的项，就必须有自动化用例。

## 二、分层与归属

| 层 | 工具 | 抓什么 | 谁写 | 耗时上限 |
|---|---|---|---|---|
| 静态构建 | `npm run build` | Vue 编译错、路由冲突、frontmatter 错 | 站点作者（随改动跑） | 60 秒 |
| 链接扫描 | 构建后临时脚本（见 TR1） | 站内 5,400+ 条 href 的死链 | 站点作者 | 30 秒 |
| 同步校验 | `npm run sync` 内建的 `check()` | 跨篇 `.md` 链接、`./assets/` 图片引用 | 站点作者 | 5 秒 |
| 结构断言 | 读产物 HTML 的脚本 | 页数、表格行数、侧栏首项、导航项数 | 站点作者 | 5 秒 |
| 人工目视 | 浏览器 | 布局、渐变、间距、深浅色 | 站点作者 | 按需 |

**没有单元 / 组件 / e2e / 压测四层。** 理由是第一节「不测」那四行。

**分层依据是「跑起来需要什么」**：全部是命令行脚本，没有需要浏览器驱动的层，所以 `test/` 目录不存在。

## 三、风险分级

| 区域 | 风险 | 判断依据 | 测到什么程度 |
|---|---|---|---|
| 同步产物完整性 | 篇数少了或目录错位，站点看起来正常但内容缺 | **错了难恢复**（覆盖式清空，没有事务） | 每次 sync 后核对篇数（219 + 220）与目录树 |
| 目录页链接 | 一条链接 404，读者点进去是空白 | **错了难恢复**（读者不会告诉你） | 每次构建后跑全量链接扫描 |
| Vue 语法冲突 | 裸 <span v-pre>`{{ }}`</span> 或裸尖括号让整页内容残缺 | **错了难恢复**（页面还在，内容没了，最隐蔽） | 每次 sync 后 grep 一遍围栏外是否还有裸 <span v-pre>`{{`</span> |
| 首页与导航 | 12 张卡片少一张，导航少一项 | 错了容易发现 | 人工目视 + 结构断言 |
| 样式与布局 | 渐变、间距、响应式错位 | 错了容易发现 | 人工目视，1512 与 1920 两个宽度 |
| 图片体积 | 产物逼近 Cloudflare 上限 | 有预警窗口 | 构建后统计文件数与单文件最大体积 |

**判断依据只有三种**：涉及钱、涉及权限、错了难恢复。本站只占第三条。

**前三项必须有自动化检查。** 只人工点一遍不算——下次改代码时没人会记得再点一遍。

## 四、出口标准

| 条件 | 要求 |
|---|---|
| AC 覆盖 | 100%；未覆盖必须写原因 + 人工验证方式 + 谁验的 |
| 高风险区域 | 三项（同步完整性 / 链接 / Vue 语法）都有脚本检查且全过 |
| 失败用例 | 0 |
| 不稳定检查 | 0；同一检查连跑两次结果不一致就修，不许「重跑就过了」当通过 |
| 未关闭缺陷 | 无 P0 / P1；P2 需人确认接受 |
| 构建产物 | 页数、文件数、单文件最大体积都在上限内 |

## 五、回归范围

| 改动类型 | 跑什么 |
|---|---|
| 只改某个 `.md` 的文案 | 构建 + 链接扫描 |
| 改导航 / 侧边栏配置 | 构建 + 链接扫描 + 结构断言（导航项、侧栏首项） |
| 改样式 | 构建 + 人工目视（1512 与 1920 两个宽度） |
| 改 `sync-content.mjs` | **全量**：sync + 构建 + 链接扫描 + 结构断言 |
| 改 `gen-notes-index.mjs` | **全量**：gen + 构建 + 链接扫描 + 表格行数断言 |
| 源库升级（新增删篇、改目录） | **全量** + 人工核对篇数与目录树 |
| 升级 VuePress / theme-hope 版本 | **全量** + 人工目视全站四屏 |
| 改部署配置 | 全量 + 一次真实部署验证 |

**改脚本、改源库、升框架一律全量。** 这三处的共同点是「一处改错，影响面说不清」。

**只改文案可以只跑构建**：唯一的风险是引入新的 Vue 语法冲突，构建会直接报。

## 六、环境与数据

| 项 | 做法 |
|---|---|
| 数据库 | 无 |
| 种子数据 | 无。测试数据就是真实内容 |
| 外部系统 | 构建时不需要；部署验证需要 Cloudflare |
| 时间 | 不涉及时间相关逻辑 |
| 清理 | 链接扫描与结构断言都用临时脚本，不落盘 |

**没有「造数据」这一步。** 内容即数据，改内容就会同时改测试对象。这是本站的特殊之处：**测试不能独立于内容存在**。

## 七、缺陷分级

**定义来自 `07-审查/01-审查清单.md`，两边必须同一套。**

| 级别 | 定义 | 卡不卡上线 | 谁修 |
|---|---|---|---|
| P0 | 广泛灾难性影响：整页内容残缺、全站构建失败、内容大面积缺失 | **必卡** | 站点作者 |
| P1 | 高概率可见缺陷：主要栏目链接 404、导航项缺失、侧栏顺序错 | **必卡** | 站点作者 |
| P2 | 有明确触发条件的中等问题：某篇深层链接断、某宽度下卡片挤压 | 人确认后可上线 | 站点作者 |
| P3 | 低风险但可行动：措辞、间距细节、图标大小 | 不卡 | 下次改动 |

**测试只定级别，不定优先级。** 先修哪个由人排。

## 八、本项目的特殊约定

**三条与模板不同，是判断结果：**

1. **验证层就两层：构建 + 脚本断言。** 模板的 `vitest/`、`playwright/`、`fixtures/`、`helpers/` 四层是为有函数、有组件、有接口的项目准备的。这个站点没有业务逻辑，可测对象只有「产物长什么样」，所以用两层覆盖到底。

2. **检查脚本按次跑，收进 TR。** 链接扫描、结构断言都是构建后跑的 Node one-liner，结论与命令原样写进 TR，可复跑。它们依赖具体的产物路径与页数，所以不固化成长期脚本——固化了就要随每次内容变化改一遍。

3. **验证与审查分两段执行。** 测试执行核对「跑起来对不对」，审查核对「产物与规格对不对」，两段结论各自落文件（TR、CR）。单人项目里两段由同一个执行者完成，但判据不同、留痕不同，不合并成一段。
